# Разработка и сообщения об ошибках

Проект — экспериментальный клиентский аддон ASUSWRT-Merlin. Сетевая логика работает в BusyBox `/bin/sh`; Node.js и Python нужны только на компьютере разработчика.

## Проверки на компьютере

Требуются Python 3.11+, Node.js, jq с регулярными выражениями, BusyBox ash, flock, GNU timeout, OpenSSL и ShellCheck 0.10.0. На Ubuntu: `jq busybox util-linux openssl shellcheck`. Для браузерных проверок нужен Playwright 1.62.1 и его Chromium; `NODE_PATH` может указывать на отдельную установку Playwright.

```sh
make test
make lint
make browser-test
make screenshots
make package
```

`make package` создаёт IPK, ZIP/TAR.GZ исходников и SHA256SUMS. `make ipk` или `sh build-ipk.sh` создаёт только IPK и обновляет закреплённый `install-online.sh`. Редактируйте шаблон `packaging/install-online.sh.in`; итоговый скрипт генерируется сборщиком. При изменении runtime/установщика обновите VERSION, код с номером версии, CHANGELOG, STATUS и фактический TEST-REPORT, затем пересоберите. IPK не включает себя, online-скрипт и документацию; это предотвращает циклическую зависимость его хеша от установщика.

Тесты сети подменяют все сетевые команды. `TT_ROOT` — файловая песочница; живые действия с ним запрещены. Аппаратные проверки требуют отдельного явного разрешения владельца роутера. Результаты mocks и снимки preview не являются аппаратными PASS.

## Отчёт об ошибке

Укажите версию аддона, CLI, модель/прошивку, действие и точное сообщение ошибки. Подойдёт диагностический отчёт панели после просмотра и обезличивания топологии. Не прикладывайте `tt://`, пароль, endpoint JSON, client TOML, закрытый ключ, полный журнал клиента или необработанный вывод NVRAM.

Для чувствительной проблемы сначала передайте автору краткое описание без секретов через приватный канал, который он явно предоставил. Если такого канала нет, создайте публичное обращение только с просьбой согласовать приватную передачу, без конфигурации и деталей эксплуатации. Проект не заявляет независимый аудит безопасности. Текущие гарантии и ограничения описаны в [docs/SECURITY.md](docs/SECURITY.md).

## Источники и лицензии

Новые контракты сверяются с кодом конкретного upstream-релиза. Сохраняйте ссылки в RESEARCH/UPSTREAM. Код другого проекта нельзя переносить без соблюдения его лицензии. Для UI используйте демонстрационные данные и собственные снимки actual HTML; не публикуйте настройки рабочего роутера.
