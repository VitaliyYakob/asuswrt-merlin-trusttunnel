# Исключения из TrustTunnel

Аддон использует верхнеуровневый список `exclusions` режима `general` официального клиента. Совпавший трафик передаётся напрямую через обычное подключение WAN. Это осознанное исключение из VPN, а не дополнительная защита.

## Ввод в панели

В разделе «Подключение» заполните списки доменов и адресов/сетей, по одной записи на строку. Для сохранённого подключения используйте отдельную кнопку сохранения исключений: ссылка tt:// и пароль повторно не требуются. При работающем клиенте пробное применение надо подтвердить после проверки доступа.

| Пример | Назначение |
| --- | --- |
| `example.com` | Домен и его поддомены, без протокола и пути. |
| `*.example.org` | Поддомены по wildcard-правилу клиента. Для самого `example.org` добавьте отдельную запись. |
| `203.0.113.10` | Отдельный IPv4-адрес. |
| `203.0.113.0/24` | IPv4-подсеть. |
| `203.0.113.10:443` | Указанный IPv4-адрес и порт. |
| `*:80` | Этот порт у любых адресов. |

`https://example.com/path` не подходит: используйте домен `example.com`. Путь конкретной страницы не фильтруется. Не вводите IPv6, регулярные выражения или произвольный URL. Аддон проверяет именно поддерживаемое подмножество официальных форматов и объясняет отказ. Пустые строки удаляются.

Широкая подсеть или общий порт могут вывести из VPN намного больше трафика, чем один сайт. `*:53` может разрешить прямые DNS-запросы. Прямой выход виден провайдеру и использует его внешний IP.

Доменные исключения зависят от DNS и правил сопоставления самого TrustTunnel. Не обещайте изоляцию страницы по пути или постоянное соответствие домена одному IP. Реальную работу выбранных исключений проверяйте с клиентского устройства; полный WAN/DNS capture пока не выполнен.

DNS берётся из сохранённой конфигурации подключения. Исключения не меняют DNS и не превращаются в `listener.tun.excluded_routes`: системная маршрутизация остаётся под управлением аддона. Выбор локальных разрешённых сетей на вкладке «Сети» — отдельный механизм доступа к локальным ресурсам, не этот список.
