## Возможности

- Нативная панель **VPN → TrustTunnel**, штатный httpd Merlin; без отдельного сервера, Docker, Node.js или Python на роутере.
- Ручной ввод, ссылка `tt://`, импорт файла, карточка сохранённого профиля и отдельное изменение транспорта/MTU/Anti-DPI. Учётные данные, DNS и сертификат не возвращаются в браузер.
- Выбор сетей, подсетей или отдельных IPv4-адресов; SSID и списки их клиентов показаны раздельно. Общий bridge сохраняет общую политику L3, отдельная подсеть не выдумывается.
- Доменные и сетевые исключения с отдельным сохранением. Действующие изменения проходят пробное применение, подтверждение или откат.
- Одна кнопка подключения/отключения; пауза и сбой клиента сохраняют запрошенные защитные правила. IPv6 блокируется на выбранном bridge целиком с явным предупреждением.
- Подписанные stable/nightly обновления CLI, пятиминутное испытание работающего VPN, подтверждение и возврат предыдущей версии. Аппаратная приёмка нового механизма испытания ещё не завершена.
- Таймеры по времени работы роутера, ограниченный журнал, показатели CPU/памяти, диагностика по разрешённому списку полей. Процесс и TUN сами по себе не означают проверенное соединение.
- Последняя проверка трафика с датой и счётчиками сохраняется в приватной истории. Устаревание объясняется отдельно; исторический успех не подтверждает текущее состояние правил.
- IPK, установка по ссылке с закреплённым SHA-256, резерв файлов перед заменой и удаление только собственных объектов. Аппаратное ускорение роутера глобально не отключается.

## Проверено

Для alpha.14: `make test preview` — 292 теста Python, JavaScript 22/35/6 групп; ShellCheck и шесть браузерных сценариев PASS. Визуально проверены синтетические desktop/mobile снимки новой строки. На роутере сначала подтверждены перенос прежнего результата, его отдельный статус `expired`, сохранность процесса/CLI/подключения/политики и сетевого состояния при hotfix. Затем выполнено настоящее обновление IPK alpha.13 → alpha.14 при уже отключённом VPN: состояние install user installed, 84 файла исходников/init совпали, сохранены все файлы конфигурации, CLI, основные маршруты, ip rules, firewall и cron. Новый пользовательский тест сайтов, перезагрузка роутера и откат этой установки не выполнялись; GitHub CI alpha.14 не запускался.

Локально и в полном GitHub CI коммита/тега alpha.13: **282 теста Python**, JavaScript 22/35/6 групп, ShellCheck, шесть браузерных сценариев, сборка пакета и поиск секретов. Снимки интерфейса содержат только демонстрационные данные.

18.10.2026 выполнено настоящее обновление IPK alpha.10 с исправлениями alpha.12 до alpha.13. В Entware добавлен `coreutils-mkfifo 9.9-2`. Конфигурация и CLI сохранены побайтово; основные маршруты, правила policy routing и cron совпали с резервом. Все файлы пакета, runtime и init сверены с исходниками. Ожидаемые правила проверены; за 10 секунд наблюдались 9 исходящих и 4 ответных пакета. Временные правила установки и её восстановительный cron удалены; ускорение HND осталось включённым.

Первоначальный кандидат выявил отсутствие `mkfifo`: внешний сценарий возврата восстановил пакет alpha.10, runtime alpha.12 и работающий VPN. Это проверка восстановления оператором, не доказательство всех внутренних ветвей отката установщика или CLI. Резерв успешной установки и явная команда возврата сохранены в приватном `/opt/ttm-setup-alpha13-20261018c`.

Предыдущие аппаратные испытания подтверждают пользовательский трафик гостевой сети и смену внешнего IP, подписанное обновление CLI 1.1.5 → 1.1.7, паузу без Интернета и восстановление, keep-config удаление IPK alpha.10 и полное удаление alpha.6. Результаты всегда относятся к конкретному испытанию в [TEST-REPORT.md](TEST-REPORT.md).

## Оставшиеся проверки

- Чистая установка IPK, удаление alpha.13, отказ настоящего postinst и повторное configure; новые внутренние ветви возврата файлов пока проверены автономно.
- Полные DNS/IPv6/WAN captures при аварии, перезагрузке, WAN/firewall reload и уже ускоренных HND-потоках; питание, USB и ранняя загрузка.
- Настоящие WebUI-сценарии двух вкладок, частичных правок и потерянного ответа; полный набор session/CSRF/WAN.
- Подтверждение, истечение и откат нового обновления CLI на роутере; длительные CPU/RSS/FIFO нагрузки. Наличие процесса/TUN и счётчиков не доказывает отсутствие утечек.
- Другие модели, более старые прошивки и ветка 3006. Выбор /32 основан на IPv4 и требует постоянного адреса.

IPv6-туннелирование, несколько профилей, GeoIP и фоновая установка обновлений не реализованы. Точный объём удалённого CI и публикации фиксируется отдельно в [TEST-REPORT.md](TEST-REPORT.md); результаты старого CI не распространяются автоматически на новые коммиты.
