# Состояние 0.3.1-alpha.9

Цель: ASUS RT-AX86U aarch64, Entware установлен. По отдельному разрешению пользователя 20.09.2026 выполнены установка, первый запуск и полное удаление на Merlin 3004.388.12_2 / kernel 4.1.52. Официальный клиент 1.1.5 был проверен по GPG-подписи. Первый контролируемый запуск выполнялся только для Home_net_dev: пользователь подтвердил открытие сайтов и изменение внешнего IP; глобальное HND ускорение оставалось включённым. После проверки alpha.6 полностью удалила аддон, приватную конфигурацию/runtime и проверенные клиентские файлы. Основная и гостевая сети, исходные маршруты/firewall, другие hooks и страница Merlin сохранились; исходящий HTTPS роутера работает. Затем alpha.6 повторно установлена в выключенном состоянии без endpoint, policy и VPN-процесса. Общие пакеты Entware сохранены.

## Исправление оформления alpha.9

На AX86U подтверждён HTTP 404 для custom CSS с query string; тот же файл без query возвращает HTTP 200 / text/css. В alpha.9 версия помещена в имя CSS-файла, ресурсы публикуются перед страницей. Добавлена проверка отдельной загрузки стилей по ссылке ASP и очистки только помеченных собственных версий. Alpha.9 установлена без перезапуска CLI; параметры/маршруты сохранены, HTTP и визуальная проверка оформления на реальном роутере прошли. Аппаратные результаты и ограничения приведены в TEST-REPORT.

## Изменения alpha.8

Добавлены постоянная дата последней успешной проверки и время установки CLI. История хранится отдельно от кандидата на установку и не разрешает установку по старому результату. SSID общей подсети имеют отдельные видимые строки и списки только своих подтверждённых Wi-Fi/DHCP клиентов. При отсутствии или неоднозначности ассоциации клиент не приписывается SSID. IPv4 /32 остаются частью общей политики bridge; отдельная адресация или Wi-Fi-настройки не создаются. Версии CSS/JS обновлены против старого кеша браузера.

## Изменения alpha.7 — локальные и аппаратные проверки

Добавлены ручное подписанное обновление CLI stable/nightly, TUN IPv4, пассивная проверка трафика/правил и раздельная инвентаризация SSID. На 30.09.2026 официальный upstream публикует stable 1.1.7 и beta 1.3.0-beta.1, но публичной nightly ARM64 нет. Панель не подменяет её beta. Схема генерируемой конфигурации остаётся основанной на 1.1.5; текущая сохранённая конфигурация работает с 1.1.7 на AX86U, совместимость всех вариантов и последующих CLI не установлена. Алгоритм и откат описаны в [CLIENT-UPDATES.md](CLIENT-UPDATES.md).

SSH-диагностика 30.09.2026 подтверждает, что Home_net (eth6/eth7) и Old-Mac-Net (wl0.2) сейчас являются участниками br0 / 192.168.73.0/24; Home_net_dev (wl0.1) — br1 / 192.168.101.0/24. Ссылка DHCP на br2 не сопровождается реально существующим интерфейсом. Это разные SSID, но на текущем роутере первые два имеют общий L3-сегмент. Панель показывает отдельные SSID и явно общую маршрутизацию. Wi-Fi/NVRAM/bridge/маршруты на роутере не менялись. Нельзя обещать независимую маршрутизацию этих SSID без изменения реальной топологии; /32 остаётся выбором устройства по IP.

По отдельному разрешению пользователя 30.09.2026 alpha.7 установлена на работающий AX86U через защищённую паузу, с приватным резервом и независимым возвратом к предыдущему коду при ошибке проверки. Из настоящей HTTPS-панели выполнено обновление CLI 1.1.5 → 1.1.7: проверены официальный digest, настоящая GPG-подпись, ELF/версия и резерв предыдущего binary; журнал успешно закрыт. Endpoint/policy, main routes/ip rules и проверенные Wi-Fi/NVRAM параметры сохранились. HND ускорение и Flow Learning остались включены. Выбрана только Home_net_dev / 192.168.101.0/24.

Проверка ожидаемых правил и счётчиков на реальном ядре прошла. Пользователь с гостевого устройства подтвердил сайты и VPN IP после обновления; во время «Паузы с блокировкой» Интернет отсутствовал, после независимого автоматического запуска восстановился с VPN IP. Это ограниченный положительный сценарий, не полный тест DNS/IPv6/ускоренных потоков или утечек в момент обновления. Автовозврат binary при ошибке запуска и восстановление после питания/USB по-прежнему проверены только mocks. Подробности — [TEST-REPORT.md](TEST-REPORT.md).

## Реализовано для локального тестирования

- Проверки готовности первого запуска, автоматическая загрузка штатного TUN, фиксированные понятные причины отказов и диагностика фактического HND. Глобальное ускорение сохраняется, выбранные потоки исключаются через SKIPLOG; старые потоки удаляются из flow cache только по выбранным bridge/их участникам. Исправлена валидация CIDR на jq 1.8.1.

- Нативная страница VPN в стиле Merlin: Обзор / Подключение / Сети / Диагностика, клавиатурные вкладки, несохранённые изменения.
- Ручное подключение, официальный tt:// v1 и импорт JSON/текстового файла; DNS только из endpoint, импортированное значение неизменяемо в форме.
- Исключения можно редактировать без повторного ввода ссылки: статус возвращает только признак сохранения и список исключений. Сервер сохраняет остальные поля подключения.
- Официальные исключения режима general: домены/wildcard, IPv4/CIDR, IPv4:порт и общий порт. Полные URL и IPv6 отклоняются с объяснением; совпадения предназначены для прямого WAN-выхода.
- Экспериментальный приватный HTTPS browser apply через штатные события, временные RSA-OAEP ключи и OpenSSL. После исправления лимита команд и parent redirect один реальный импорт endpoint подтверждён на httpd AX86U: succeeded/saved, JSON 0600 и очистка ключа. Остальные сценарии авторизации/отказов требуют аппаратной проверки.
- Ревизии, результаты операций с ID, ограниченная история, защита от повторного исполнения. После сбоя связи UI сообщает неизвестный результат, а не успех по таймеру.
- Активные изменения endpoint/policy через журнал и резерв, guards старых/новых источников, пробное применение на 180 секунд, подтверждение и откат. Неуспешный откат сохраняет карантин. Проверено моделью команд; это не доказательство отсутствия пакетных утечек.
- Schema4: сети с видимыми пользовательскими SSID, неизменяемым bridge и идентификатором состава сети; служебные BSS отфильтрованы по штатному Merlin 388. DHCP для отсутствующего bridge помечается предупреждением. Выбор DHCP-устройств по IPv4 /32; локальные исключения без отмены фильтрации Merlin. Schema1/2/3 совместимы.
- Повтор запуска с задержками 60/120/240/480/900 секунд. Guards восстанавливаются и во время ожидания; ручной запуск сбрасывает ожидание.
- Отчёт без endpoint/журнала клиента: инструменты, версии, присутствие guards, более ранние IPv4 rules, ожидаемая версия и записанный hash клиента. Эти признаки не доказывают VPN-соединение.
- Проверка локальной подписи и ручное обновление клиента через официальный релиз по закреплённому ключу upstream; предыдущий binary, журнал восстановления и возврат при ошибке запуска. Автоматической установки нет.
- Git-ветка, регрессии, preview/архив и расширенное определение CI. Исходный Template сохранён.

## Практические ограничения

Полное сохранение подключения заменяет его целиком; отдельная кнопка изменяет только исключения. Секреты не читаются обратно в браузер. Передача большого сертификата может занимать минуты. Транспорт ограничен 64 КиБ и 2 часами. Автоматический откат проверяется cron раз в минуту, поэтому начинается не обязательно ровно на 180-й секунде; после перезагрузки он зависит от Entware и корректных часов. Неизвестные занятые ресурсы не перехватываются ради восстановления.

Выбор устройств работает по IP, требует DHCP reservation в Merlin. Изменение SSID сохраняет идентификатор; смена состава bridge/адресации требует пересмотра политики, не переносит её автоматически на новую топологию. Старые сохранённые CIDR сами по себе не защищают новые адреса после изменения DHCP/подсетей вне аддона.

Не реализованы: автоматическая проверка полноценного VPN-соединения с LAN, внешние подписочные/GeoIP-списки, несколько профилей/failover, IPv6-туннелирование и фоновые обновления. Исключения не проверены реальным трафиком. Linux packet tests в данной macOS-среде не выполнялись; mock-тесты их не заменяют.

## Удаление alpha.6

Добавлены dry-run, keep-config и purge с отдельными подтверждениями возврата обычной маршрутизации и удаления данных. Детали и границы очистки: [UNINSTALL.md](UNINSTALL.md). Локальные 184 Python tests, JS, браузер и ShellCheck прошли. На рабочем роутере dry-run и purge выполнены: контроллер, конфигурация, runtime, проверенные клиентские файлы, WebUI, cron, init и собственные правила отсутствовали. Проверки сети и HTTPS после удаления прошли. Затем alpha.6 повторно установлена: клиент 1.1.5, WebUI, cron и init присутствуют, но endpoint/policy/VPN отключены. Alpha.6 сохранена как локальный релиз.
