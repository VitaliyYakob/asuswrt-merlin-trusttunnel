# Состояние 0.3.1-alpha.6

Цель: ASUS RT-AX86U aarch64, Entware установлен. По отдельному разрешению пользователя 20.09.2026 выполнена установка на Merlin 3004.388.12_2 / kernel 4.1.52. Официальный клиент 1.1.5 проверен по GPG-подписи и запускается с --version. Alpha.5 установлена; обнаружены два реальных bridge. Первый контролируемый запуск выполнен только для Home_net_dev: клиент/TUN и счётчики гостевого трафика работают; пользователь подтвердил открытие сайтов и изменение внешнего IP. Глобальное HND ускорение осталось включённым. После пятиминутного теста VPN автоматически отключён, исходные маршруты/firewall восстановлены; подключение, пользовательские исключения и выбор гостевой сети сохранены. Полная защита от утечек и производительность не проверены.

## Реализовано для локального тестирования

- Проверки готовности первого запуска, автоматическая загрузка штатного TUN, фиксированные понятные причины отказов и диагностика фактического HND. Глобальное ускорение сохраняется, выбранные потоки исключаются через SKIPLOG; старые потоки удаляются из flow cache только по выбранным bridge/их участникам. Исправлена валидация CIDR на jq 1.8.1.

- Нативная страница VPN в стиле Merlin: Обзор / Подключение / Сети / Диагностика, клавиатурные вкладки, несохранённые изменения.
- Ручное подключение, официальный tt:// v1 и импорт JSON/текстового файла; DNS только из endpoint, импортированное значение неизменяемо в форме.
- Исключения можно редактировать без повторного ввода ссылки: статус возвращает только признак сохранения и список исключений. Сервер сохраняет остальные поля подключения.
- Официальные исключения режима general: домены/wildcard, IPv4/CIDR, IPv4:порт и общий порт. Полные URL и IPv6 отклоняются с объяснением; совпадения предназначены для прямого WAN-выхода.
- Экспериментальный приватный HTTPS browser apply через штатные события, временные RSA-OAEP ключи и OpenSSL. После исправления лимита команд и parent redirect один реальный импорт endpoint подтверждён на httpd AX86U: succeeded/saved, JSON 0600 и очистка ключа. Остальные сценарии авторизации/отказов требуют аппаратной проверки.
- Ревизии, результаты операций с ID, ограниченная история, защита от повторного исполнения. После сбоя связи UI сообщает неизвестный результат, а не успех по таймеру.
- Активные изменения endpoint/policy через журнал и резерв, guards старых/новых источников, пробное применение на 180 секунд, подтверждение и откат. Неуспешный откат сохраняет карантин. Проверено моделью команд; это не доказательство отсутствия пакетных утечек.
- Schema4: сети с видимыми пользовательскими SSID, неизменяемым bridge и идентификатором состава сети; служебные BSS отфильтрованы по штатному Merlin 388. DHCP для отсутствующего bridge помечается предупреждением. Выбор DHCP-устройств по IPv4 /32; локальные исключения без отмены фильтрации Merlin. Schema1/2/3 совместимы.
- Повтор запуска с задержками 60/120/240/480/900 секунд. Guards восстанавливаются и во время ожидания; ручной запуск сбрасывает ожидание.
- Отчёт без endpoint/журнала клиента: инструменты, версии, присутствие guards, более ранние IPv4 rules, ожидаемая версия и записанный hash клиента. Эти признаки не доказывают VPN-соединение.
- Проверка локальной подписи клиента по закреплённому ключу upstream, предыдущий binary перед заменой и путь отката; никаких автоматических обновлений.
- Git-ветка, регрессии, preview/архив и расширенное определение CI. Исходный Template сохранён.

## Практические ограничения

Полное сохранение подключения заменяет его целиком; отдельная кнопка изменяет только исключения. Секреты не читаются обратно в браузер. Передача большого сертификата может занимать минуты. Транспорт ограничен 64 КиБ и 2 часами. Автоматический откат проверяется cron раз в минуту, поэтому начинается не обязательно ровно на 180-й секунде; после перезагрузки он зависит от Entware и корректных часов. Неизвестные занятые ресурсы не перехватываются ради восстановления.

Выбор устройств работает по IP, требует DHCP reservation в Merlin. Изменение SSID сохраняет идентификатор; смена состава bridge/адресации требует пересмотра политики, не переносит её автоматически на новую топологию. Старые сохранённые CIDR сами по себе не защищают новые адреса после изменения DHCP/подсетей вне аддона.

Не реализованы: автоматическая проверка полноценного VPN-соединения с LAN, внешние подписочные/GeoIP-списки, несколько профилей/failover, IPv6-туннелирование и автоматическая загрузка обновлений. Исключения не проверены реальным трафиком. Linux packet tests в данной macOS-среде не выполнялись; mock-тесты их не заменяют.

Alpha.6 собрана как локальный релиз.
