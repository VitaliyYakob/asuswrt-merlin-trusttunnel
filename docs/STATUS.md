# Состояние 0.3.1-alpha.11

Исправление alpha.11 применено на RT-AX86U как точечное обновление runtime/payload без остановки клиента. Статус снова публикуется по расписанию; изолированный тест зависания на firmware ash/GNU timeout прошёл. PID/starttime клиента, приватная конфигурация и main routes сохранены; cron восстановил отсутствовавшее собственное правило 17100 из прежней политики. Проверены 257 Python tests, JavaScript, ShellCheck и браузерные сценарии; финальный пассивный аппаратный тест подтвердил ожидаемые правила и 8/7 пакетов через TUN; подробности — [TEST-REPORT.md](TEST-REPORT.md). Регистрация opkg остаётся alpha.10-1; новый IPK alpha.11 собран локально. Публичный релиз alpha.10 и его файлы не изменены.

Имя проекта: **asuswrt-merlin-trusttunnel**. Публичный [репозиторий](https://github.com/VitaliyYakob/asuswrt-merlin-trusttunnel), опубликованный [предварительный релиз alpha.10 с файлами установки](https://github.com/VitaliyYakob/asuswrt-merlin-trusttunnel/releases/tag/v0.3.1-alpha.10). На действующем RT-AX86U работают **runtime alpha.11 (hotfix поверх IPK alpha.10) / официальный CLI 1.1.7**, выбранный гостевой VPN включён. Конфигурация и история CLI сохранены побайтово; после установки проверены реальные пакеты через tt0 и ожидаемые правила.

## Готово

- Нативная страница VPN в стиле Merlin: Обзор / Подключение / Сети / Диагностика.
- Ручной ввод, официальный tt:// v1, импорт файла и приватное сохранение через HTTPS/RSA-OAEP. Пароль, username, DNS и сертификат не читаются обратно в браузер. Исключения можно сохранять отдельно без повторного ввода подключения.
- Маршрутизация выбранных bridge+IPv4 подсетей/адресов. SSID показаны отдельными строками; списки устройств строятся по подтверждённой Wi-Fi-ассоциации и DHCP. Для SSID общего bridge сохраняется общая политика L3, отдельные подсети не выдумываются.
- IPv6 блокируется на выбранном bridge целиком; это явно объясняется в форме. Пауза/сбой клиента не намеренно освобождает guards, явное отключение освобождает.
- Активное применение через persistent journal, резерв, 180-секундное испытание, подтверждение или откат. Неуспешное восстановление удерживает карантин.
- Ручной stable/nightly updater официального ARM64 CLI с повторной проверкой metadata, хеша, GPG-подписи/ключа, архитектуры и версии; резерв предыдущего binary и recovery journal. Beta не выдаётся за nightly. Даты установки и успешного поиска сохраняются отдельно от разрешающего установку кандидата.
- Внутренний IPv4 TUN, счётчики и пассивная проверка ожидаемых правил/обмена. Это не тест утечек и не подтверждение связи по одному наличию процесса/TUN.
- Selective SKIPLOG для VPN-потоков на HND без глобального отключения ускорения. Контроль чужих таблиц/цепочек/интерфейсов, исключение unscoped/global flush.
- Dry-run, keep-config и purge удаления собственного кода/данных/правил с отдельными подтверждениями; чужие hooks, общие пакеты и Wi-Fi сохраняются.
- IPK aarch64-3.10, установщик по ссылке с закреплённым SHA-256 IPK и начальным CLI 1.1.5, проверенным по хешам/GPG. Нет автоматического VPN-start, понижения существующего CLI или вложенного opkg в maintainer scripts.
- Русский README, требования и обе инструкции установки, демонстрационные снимки без конфигурации автора, CONTRIBUTING и план публикации/черновика prerelease. Template и сырые журналы удалены из текущей поставки, сохранены в предыдущей Git-истории. Релиз не включает секреты и официальный binary.
- Публичные исходники в GitHub; полный [удалённый CI](https://github.com/VitaliyYakob/asuswrt-merlin-trusttunnel/actions/runs/36783552408) окончательного релизного коммита прошёл на Ubuntu 24.04, включая браузерные проверки, упаковку и поиск секретов. Файлы релиза и анонимное скачивание установщика/IPK/SHA256SUMS проверены; online-установка на роутере отдельно не выполнялась.

## Подтверждено на роутере

RT-AX86U / Merlin **3004.388.12_2** / kernel 4.1.52 / Entware: native установка, сохранение подключения, гостевой трафик и смена внешнего IP, подписанное CLI-обновление 1.1.5 → 1.1.7, отсутствие Интернета выбранной сети при паузе и восстановление после запуска, полное удаление alpha.6, HTTP/CSS и отображение отдельных SSID alpha.9. HND ускорение оставалось включённым. Каждый результат ограничен конкретным испытанием в [TEST-REPORT.md](TEST-REPORT.md).

Alpha.10: помимо offline-root проверок выполнена настоящая установка IPK поверх собственного native аддона и keep-config удаление пакета в автоматической ветке возврата к alpha.9. Повторная установка принята: 36 исходящих / 39 ответных пакетов за 10 секунд, ожидаемые правила проверены, main routes/ip rules и конфигурация совпали с резервом. HW Acceleration и Flow Learning включены. HTTPS CSS вернул 200 / text/css и bytes исходника. [Точный объём и первая ошибка внешнего контрольного сценария](TEST-REPORT.md#установка-ipk-alpha10-на-rt-ax86u--01102026).

## Ограничения

Минимум поддерживаемой поставки — Merlin **3004.388.12**. Более старые прошивки, другие модели и ветка 3006 аппаратно не испытывались; наличие Addons API с 384.15 не доказывает совместимость сетевой логики.

Первоначальная загрузка CLI из postinst на чистом роутере, IPK → IPK upgrade, configure после настоящего сбоя postinst и purge alpha.10 остаются непроверенными. Также не завершены ошибочный startup rollback на реальном ядре, перезагрузка/питание/USB, полный DNS/IPv6/WAN capture, уже ускоренные потоки, WAN/firewall reload и независимый аудит безопасности. Исключения подтверждались сохранением и ограниченным пользовательским сценарием, их полная пакетная область не проверена. Различные варианты конфигураций будущих CLI не гарантируются.

Выбор /32 работает по IPv4, требует постоянного адреса; это не MAC-идентификация устройства. Изменение топологии/адресации вне аддона требует пересмотра политики. Для полноценного VPN-теста нужно устройство выбранной LAN/guest сети.

Не реализованы IPv6-туннелирование, несколько профилей/failover, GeoIP/подписочные списки и фоновая установка обновлений. Linux packet tests на host macOS не выполнялись. Конкретные результаты локальных, аппаратных и удалённых проверок приведены в [TEST-REPORT.md](TEST-REPORT.md); наличие workflow само по себе не подтверждает его успешность.
