# Архитектура 0.2.2-alpha.1

## Потоки данных

- Ручные поля/tt:// → чистый JavaScript parser → endpoint schema1 → локальный JSON download → приватный SSH import → TOML → официальный клиент.
- Выбранные сети → policy schema3 → non-secret amng_custom → start_apply.htm → service-event → allowlist dispatcher → shell-контроллер.
- Контроллер → ограниченный status.json → XMLHttpRequest страницы. Статус не содержит username, password, ссылку, сертификат или TOML.
- `/www/user/userN.asp` и ресурсы `/www/user/trusttunnel/` обслуживает штатный httpd Merlin. Страница находится в VPN. Отдельного сервера и собственной авторизации нет.

## Политика нескольких сетей

`networks` содержит 1–16 уникальных `lan_if`, каждый с частными каноническими IPv4 CIDR. Общий лимит — 32 записи. Контроллер принимает schema1 с `lan_if/sources` и schema2; при импорте отключённой политики они преобразуются в schema3 с резервной копией и удалением устаревшего DNS-поля.

Пары bridge+source разворачиваются в правила `ip rule ... from CIDR iif BRIDGE lookup 871` с приоритетами 17100–17131. Цепочки DNS/FORWARD ограничены соответствующими ingress bridge и source. Возвратный поток разрешён из tt0 в выбранную сеть. SNAT в POSTROUTING ограничен source и выходом tt0 (в этой цепочке нельзя использовать ingress `-i`). IPv6 REJECT ограничен всеми выбранными bridge целиком. Невыбранные bridge не получают правил TTM.

Собственный `prohibit default` остаётся в таблице 871 при паузе/отсутствии TUN. Основной default route, dnsmasq, resolv.conf, fwmarks и conntrack глобально не меняются. Защита зависит от реального порядка firewall и аппаратного ускорения — обязательны пакетные аппаратные проверки.

## Владельцы

TrustTunnelClient создаёт tt0 и отвечает за транспорт/TLS. Генератор использует `use_existing=false`, `included_routes=[]`, `excluded_routes=[]`, `change_system_dns=false`, `has_ipv6=false`, `skip_verification=false`. Пустые included_routes подавляют управление таблицей 880 upstream-клиентом; маршруты, DNS DNAT, SNAT и guards принадлежат аддону.

Конфигурация: `/jffs/addons/trusttunnel/config/` (0700), JSON и `.previous` (0600). Runtime: `/tmp/trusttunnel/` (0700). При включённом аддоне изменение endpoint/policy запрещено. В контроллере flock; дочерний клиент закрывает lock FD. PID сверяется по starttime и executable realpath.

## Границы интерфейса

Импорт tt:// не запускает setup_wizard, не использует shell и не отправляет ссылку по сети. Он проверяет формат, а не доступность сервера. Проверку сертификатной цепочки выполняет клиент. Поля name и предупреждения отображаются как текст. Browser downloads создают приватную по содержанию, но не гарантированно 0600 по правам копию — пользователь ограничивает права перед переносом.

Non-secret policy проходит Addons API с лимитом 2999 ASCII символов на значение и 8 KiB всего. При нехватке места доступен JSON export/SSH. Shared settings других аддонов сохраняются из снимка страницы; конкурирующие записи между несколькими вкладками не являются общей атомарной транзакцией. До отдельного транспорта не редактируйте одновременно политики разных аддонов.

Инвентаризация читает sysfs bridge/brif и IPv4-адреса, а также только NVRAM wlN_ifname, wlN_vifnames, wlN.M_ifname и ssid фактических участников bridge. Номер bridge не используется для угадывания номера SSID. Неоднозначные соответствия не получают придуманного имени. UI хранит связь в модели памяти; редактируемого bridge-поля нет.

Пользовательский сертификат дополнительно проверяется на роутере до импорта и генерации TOML: каждый PEM-блок должен успешно разбираться `openssl x509`. Некорректный первый или последующий блок, посторонний текст и незакрытые блоки отклоняются. Без OpenSSL непустой custom certificate не принимается; пустое поле использует обычное хранилище доверия клиента. Эта проверка предотвращает молчаливый fallback upstream при ошибке разбора, но не заменяет проверку TLS при соединении.

## DNS только из конфигурации подключения

Schema3 маршрутизации не содержит DNS. Порт 53 TCP/UDP выбранных источников направляется на **внутренний транзитный адрес 192.0.2.53** в TUN. Это не адрес внешнего DNS-сервера и не значение dns_upstreams; его не нужно вводить пользователю. Core TrustTunnel перехватывает DNS и передаёт запрос обработчику с endpoint.dns_upstreams, включая настроенные DoH/DoT и нестандартные порты. Проверка перед запуском отвергает локальную коллизию транзитного адреса.

Для этого пути DNS конфигурации обязателен при запуске. В стабильном коде v1.1.5 при пустом dns_upstreams запрос может идти на исходный адрес назначения; поэтому аддон не запускает такое подключение и не добавляет запасного резолвера. Пустой список при импорте сохраняется. Значения DNS не публикуются в status.json, поскольку URL резолвера может содержать приватные параметры.
