# План реализации 0.3 — 2026-09-20

Запрос пользователя: выполнить ранее предложенные этапы. Исходная версия: 0.2.2-alpha.1. Пользователь отложил доступ к AX86U до отдельного сообщения; аппаратная приёмка NOT RUN. Результат локального этапа: [STATUS.md](STATUS.md), проверки: [TEST-REPORT.md](TEST-REPORT.md).

## Порядок и критерии

1. Операции с ID, ревизия конфигурации, структурированная диагностика без секретов. Отправленная команда не считается завершённой по таймеру. Повтор одного ID не выполняет действие дважды.
2. Приватное сохранение через штатный httpd: HTTPS/Web Crypto, временный RSA-OAEP SHA-256 ключ роутера, шифрованные блоки, ограниченный последовательный транспорт через service-event. `amng_custom` не используется новым каналом. Пароли не передаются в argv/NVRAM/публичный статус. Проверить переполнение, повторы, истечение, подмену, частичный импорт и конфликт ревизий.
3. Транзакционное изменение политики: отдельные временные IPv4/IPv6 guards для объединения старых и новых сетей; журнал и резерв до изменения; обновление только собственных правил; проверка; подтверждение либо восстановление прежней политики. При неполном восстановлении guards остаются. Отдельно проверить восстановление незавершённой транзакции.
4. WebUI: Обзор / Подключение / Сети / Диагностика, состояние изменений, импорт файла, подтверждение операции, выбор устройств с привязкой IP, исключения локальных ресурсов без обхода изоляции Merlin.
5. Эксплуатация: ограниченные повторные попытки, диагностика совместимости, версии, безопасный отчёт, проверка подписи клиента и сохранение предыдущего бинарника, воспроизводимые проверки в CI.
6. Аппаратная проверка: настоящий HTTPS/httpd/CSRF/service-event, DNS/TLS/TUN, выбранные/невыбранные сети, IPv6, firewall reload, WAN loss, перезагрузка, Entware и ускорение HND. Без устройства результат не обозначается PASS.

## Ограничения приватного транспорта

В исходниках Merlin `handle_notifications()` использует `char nv[256]`, копирует команду в `last_rc_service` и передаёт имя службы в `service-event`. Поэтому в команде допустимы только идентификаторы и шифртекст; длина ограничивается до передачи. Источник: https://github.com/RMerl/asuswrt-merlin.ng/blob/main/release/src/router/rc/services.c . HTTP-обработчик: https://github.com/RMerl/asuswrt-merlin.ng/blob/main/release/src/router/httpd/web.c . Фактический контракт целевой прошивки требует проверки.

RSA-OAEP применяется стандартными Web Crypto/OpenSSL. Данные каждого блока привязаны к сессии и позиции; завершение требует всех блоков. Временный закрытый ключ и расшифрованная конфигурация существуют только в каталоге 0700 с файлами 0600. Старый ключ уничтожается при завершении/истечении; публичный ключ не содержит секрета. Канал доступен только в безопасном контексте браузера; HTTPS-аутентификация Merlin остаётся обязательной границей доверия. Передача крупных сертификатов может занимать заметное время из-за ограничения штатного события.

## Границы проверки

Модель сетевых команд проверяет порядок и область изменений, но не прохождение пакетов. Изолированные Linux-проверки и аппаратные испытания учитываются раздельно. Запрет редактирования активной политики снимается только для проверенного транзакционного пути; обычный импорт остаётся запрещён при включённом аддоне.
