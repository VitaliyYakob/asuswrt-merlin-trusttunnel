## Что проверено регрессиями

Старый single-bridge план совпадает с эквивалентной schema2 политикой. Для основной и трёх гостевых сетей выдаются уникальные приоритеты; при выборе части сетей остальные bridge не появляются в guards/DNS. Проверены повторное применение, очистка своих правил, сохранение чужих объектов, восстановление rp_filter, предел 32 source rules, обнаружение реальных CIDR и отсутствие обращения к сети хоста при TT_ROOT.

При отказе client preflight refresh восстанавливает guards и не запускает клиент; pause не зависит от наличия endpoint/binary. Ошибка backup оставляет конфигурацию/hook прежними; восстановление из `.previous` сохраняет вход до перезаписи резерва. Непустые PEM проверяются как X.509 по каждому блоку, включая повреждённый второй сертификат. Права временных files/dirs — 0600/0700, stdout/stderr/argv не раскрывают тестовые секреты.

Проверки отклоняют склеенные JSON-документы, некорректные hostname/IP/CIDR/DNS, дубли bridge, пустой выбор, превышения лимитов и неподтверждённую блокировку IPv6. В браузере подтверждена блокировка редактирования активной политики и отсутствие ложной надписи «Connected» по одному TUN.

DNS из подключения сохраняются точно, включая DoH/DoT и порты. Пустой список не заменяется значением по умолчанию: импорт возможен, запуск отклоняется до замены runtime-конфигурации. Старые политики нормализуются в schema3 без отдельного DNS с сохранением резерва. Проверены DNS DNAT для выбранных сетей, отказ при совпадении внутреннего транзитного адреса с локальным адресом и отсутствие доступа к сети хоста в TT_ROOT. Прохождение DNS-пакетов через настоящий TrustTunnel этими тестами не подтверждается.

SSID сопоставляются с фактическими членами bridge и настройками интерфейсов на фикстурах AX86U. Проверены общие bridge для нескольких SSID, неоднозначные соответствия, Unicode, отсутствие выдуманных br0–br3 при пустом обнаружении. В браузере нет отдельного DNS маршрутизации и полей редактирования bridge; подмена DOM не меняет импортированный DNS или bridge в экспорте. SSID с HTML отображается как текст. Пропавшую выбранную сеть можно снять с выбора отдельно, сохранив остальные; повторно выбрать её нельзя до обнаружения на роутере.

## Среда

macOS arm64; Python **3.14.7**, Node **22.23.1**, jq **1.7.1-apple**, Playwright **1.62.1**, Chromium **151.0.7922.34**.

На старте отсутствовали flock и BusyBox. Во временном каталоге были собраны реальные BusyBox **1.37.0** (ash/sh) и flock **0.4.0**. Исходники проверены SHA-256, системный PATH/глобальные пакеты не менялись. Сборка BusyBox адаптирована к Darwin; код ash не изменялся. Это не BusyBox роутера и не Linux kernel. Подробности происхождения и сборки: [HOST-TEST-ENVIRONMENT.md](HOST-TEST-ENVIRONMENT.md).

Для повтора в этой сессии можно загрузить `/tmp/ttm-test-deps/env.sh`; каталог временный. Для независимого воспроизведения используйте перечисленные зависимости на Linux/macOS, затем `make test` и `make browser-test`. Chromium запускался с разрешением локального IPC: обычная macOS sandbox запрещает его MachPort. Доступ к роутеру при этом не выполнялся.

## Практический предел результата

`tests/mock_net.py` — модель сетевых команд, **не симулятор пакетного трафика и не эмулятор ASUS**. Browser suite загружает HTML в Chromium; она не исполняет ASP-теги настоящего httpd Merlin и не проверяет его аутентификацию. Приватное browser-only применение подключения не реализовано: JSON применяется через SSH.

Шапка и меню ASUS в автономном предпросмотре — локальная визуальная оболочка, а не прошивка. Стили основной формы ограничены классами аддона; их совместимость с реальными стилями и навигацией установленной версии Merlin ещё не проверена на роутере.
