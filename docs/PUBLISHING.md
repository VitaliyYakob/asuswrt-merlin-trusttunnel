# Подготовка и публикация на GitHub

Имя: `VitaliyYakob/asuswrt-merlin-trusttunnel`, основная ветка: `main`. Локальная рабочая ветка — `codex/recommended-improvements`. Документ описывает подготовку и публикацию новых версий; workflow создаёт черновик релиза, а его публичный выпуск выполняется по разрешению автора.

## До публикации

1. Проверить текущие исходники, Git-историю и состав архивов на секреты. Gitleaks использует общие правила и дополнительное правило буквальных tt://; разрешена только точная опубликованная контрольная сумма исходников flock. Не исключать целые тестовые каталоги.
2. Выполнить `make test`, `make lint`, `make browser-test`, `make screenshots`, `make package`. Визуально посмотреть снимки; в них должны оставаться только демонстрационные сети и `vpn.example.com`.
3. Проверить номер VERSION, хеш IPK в `install-online.sh` и SHA256SUMS, отсутствие бинарника клиента/частных конфигураций. При несоответствии пересобрать до коммита.
4. Создать коммит и тег `v<VERSION>`. Все контрольные суммы должны относиться к этому исходному состоянию.

## После явного разрешения автора

Создать репозиторий на аккаунте автора, используя MIT и описание «Нативная веб-панель клиента TrustTunnel для ASUSWRT-Merlin. Экспериментальный проект». Отправить согласованную ветку в `main`, настроить защиту ветки и включить Issues. Все публичные описания, заметки к релизам и шаблоны обращений вести на русском. Не добавлять приватные данные и ранее локальные резервные копии.

Процесс «Автономные проверки» (`ci.yml`) определяет проверки и сканирование секретов. Его наличие не означает успешный удалённый запуск: дождаться результатов GitHub Actions и устранить реальные ошибки. Процесс «Подготовка релиза» (`release.yml`) запускается вручную для существующего тега и создаёт **черновик предварительного релиза** с IPK, ZIP/TAR.GZ и SHA256SUMS; он проверяет совпадение генерируемого установщика с коммитом.

Проверить черновик релиза, ограничения alpha и файлы. Публикация черновика — отдельное явное действие автора. Команда установки по ссылке начинает работать только после доступности IPK по закреплённому release URL. До этого не считать HTTP 404 дефектом самого пакета.

## Критерии первого публичного релиза

- README на русском с участием Codex, зависимостями, командами установки/удаления, минимальной поддерживаемой прошивкой и точной проверенной конфигурацией.
- Реальные границы тестов: установка IPK alpha.10 поверх собственного native аддона, keep-config удаление и возврат подтверждены отдельно от offline-root проверки. Полная матрица IPK, включая чистую установку/upgrade/purge, ещё не завершена.
- Снимки без рабочего сервера, SSID, адресации и имён устройств автора.
- Официальный CLI не включён в репозиторий; его первоначальная загрузка проверяется по закреплённым хешам и GPG-подписи.
- В релизе IPK и соответствующие ему исходники/SHA256SUMS; сборочные и rollback-каталоги не опубликованы.
