# Предварительный релиз 0.3.1-alpha.11

Экспериментальный клиентский аддон TrustTunnel для ASUSWRT-Merlin, разработанный совместно с Codex.

- Устранено бесконечное ожидание NVRAM при определении Wi-Fi: ограничение времени, принудительное завершение зависшего читателя, отказ от частичного вывода и пауза перед повторными запросами после ошибки.
- Сбор сведений о сетях и диагностики изолирован и ограничен по времени. Основной статус клиента публикуется даже при недоступных дополнительных данных; дочерние читатели не удерживают блокировку контроллера.
- «Обновить данные» запрашивает новый статус. Полная дата последнего обновления и понятное сообщение заменили неоднозначное предложение обновить контроллер.
- При недостоверных сведениях о сетях редактирование маршрутизации временно запрещено; отказ инвентаризации не замораживает всю панель.

Локально прошли 257 Python tests, JavaScript, ShellCheck и полный браузерный набор. На RT-AX86U / Merlin 3004.388.12_2 применён точечный hotfix без остановки CLI 1.1.7: конфигурация, PID/starttime клиента и main routes сохранились, публикация статуса восстановлена. Плановая задача также восстановила отсутствовавшее собственное правило 17100 из сохранённой политики. Это не проверка opkg upgrade: его регистрация пока остаётся alpha.10-1. Полный объём и ограничения — в [отчёте](https://github.com/VitaliyYakob/asuswrt-merlin-trusttunnel/blob/main/docs/TEST-REPORT.md).

Первичная причина единичного зависания внутри firmware NVRAM не установлена. Полные испытания утечек, питания/USB и других моделей не завершены. Минимальная поддерживаемая прошивка поставки — 3004.388.12. Этот файл готовит следующий релиз; публикация alpha.11 ещё не выполнялась.
