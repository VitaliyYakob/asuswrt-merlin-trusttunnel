# Установка asuswrt-merlin-trusttunnel

## Предварительная проверка

Поддерживаемая цель: RT-AX86U, ARM64, Merlin 3004.388.12 или новее в этой ветке. Минимум выбран по проверенной базе; совместимость более старых прошивок не доказана. Проверяются Linux/aarch64, Merlin Addons API, JFFS scripts, Entware `aarch64-3.10` и отсутствие активного VPN/транзакции. Ветка 3006 проходит проверку возраста прошивки, но аппаратно не испытывалась.

Установите Entware штатным способом, включите JFFS custom scripts и HTTPS. Выполняйте SSH-установку из основной сети. Для обновления аддона нажмите «Отключить VPN», не «Пауза с блокировкой»: пауза сохраняет активную политику и не разрешает замену кода установщиком. Все действия ограничены этим аддоном и его зависимостями; прошивка, Wi-Fi и WAN не перенастраиваются.

## По ссылке

```sh
curl -sfL https://raw.githubusercontent.com/VitaliyYakob/asuswrt-merlin-trusttunnel/main/install-online.sh | sh -s -- --lab-only
```

Скрипт из `main` содержит версию, имя и SHA-256 конкретного IPK. Обновление ссылки на новый релиз выполняется при подготовке релиза, а не выбором непроверенного `latest`. До распаковки проверяется хеш IPK. Он подтверждает соответствие пакету, закреплённому в полученном установщике; подписи самого IPK пока нет. Доверие к первому скрипту основано на выбранном репозитории и HTTPS.

Затем отдельный подготовитель устанавливает объявленные зависимости Entware, сохраняет список до/после и при необходимости заменяет минимальный jq. Он запускается **до** `opkg install`, поэтому не пытается повторно захватить блокировку opkg из postinst. При ошибке исполнения проверяйте код возврата; сообщение «Installed with VPN disabled» появляется только после успешного opkg.

Команда загрузки требует опубликованного релиза с тем же тегом, который закреплён в скрипте. Для проверки исходников до выпуска релиза используйте собранный IPK.

## Пакетом IPK

Скачайте IPK и `SHA256SUMS` из одного релиза. На Linux/роутере:

```sh
sha256sum asuswrt-merlin-trusttunnel_0.3.1-alpha.10-1_aarch64-3.10.ipk
```

Сравните значение со строкой этого файла в `SHA256SUMS`. На macOS вместо `sha256sum` можно использовать `shasum -a 256`. Перенесите проверенный пакет на роутер по SSH, затем:

```sh
opkg update
opkg install /tmp/asuswrt-merlin-trusttunnel_0.3.1-alpha.10-1_aarch64-3.10.ipk
```

IPK не содержит официальный бинарник CLI. При первой установке postinst скачивает закреплённый 1.1.5 и проверяет хеш архива, GPG-подпись/отпечаток ключа, хеш бинарника и ELF64 aarch64. Для этого нужен доступ к GitHub. Уже установленный собственный CLI с корректным digest-файлом сохраняется. Неизвестный/повреждённый файл не перезаписывается автоматически.

Установочные источники пакета находятся в `/opt/share/asuswrt-merlin-trusttunnel`; контроллер и приватные настройки — в `/jffs/addons/trusttunnel`; CLI — в `/opt/trusttunnel/bin`. Пакет не владеет общей директорией JFFS и не кладёт секреты в opkg payload. Аддон сохраняет прежний собственный код с исходными правами в `install-backups` перед заменой. Это не атомарная транзакция всей прошивки: если postinst не завершился, требуется устранить причину и повторить конфигурацию пакета.

### Конфликт минимального jq

`jq-full` и минимальный `jq` используют одни и те же файлы. Если установлен минимальный jq, перед ручным IPK загрузите архив **исходников того же релиза**, проверьте его SHA-256, распакуйте и запустите из каталога исходников:

```sh
sh tools/prepare-entware.sh --lab-only
```

Подготовитель скачивает оба пакета jq **до** удаления минимального, не использует принудительное удаление зависимостей, а при ошибке установки jq-full пытается восстановить прежний jq из локального IPK. Каталог с пакетами восстановления и списком изменений показан в выводе. Если `opkg remove jq` отказывается из-за других пакетов, сначала разберитесь с их зависимостями; принудительное удаление не требуется этому аддону.

Далее повторите `opkg install` вашего IPK. Для стандартной установки без конфликтов отдельный подготовитель не нужен.

## Из исходников

После проверки SHA-256 и распаковки архива релиза:

```sh
sh tools/setup-router.sh --lab-only
```

Использует тот же подготовитель зависимостей, закреплённый официальный клиент и `install.sh`; не регистрирует аддон в opkg. `sh install.sh --lab-only` устанавливает только панель/контроллер и предполагает, что зависимости и проверенный CLI уже подготовлены.

## Повтор, обновление и восстановление

Полный установщик требует выключенного аддона и отсутствия незавершённого обновления клиента. Резервы перед заменой остаются в `/jffs/addons/trusttunnel/install-backups/`; состояние подключения сохраняется. Откат кода выполняйте по инструкции конкретного резерва, при явно выключенном VPN. Новый непроверенный код не считается установленным по одному наличию файлов.

Если opkg оставил пакет в состоянии unpacked из-за отказа postinst:

```sh
opkg configure asuswrt-merlin-trusttunnel
```

Эта команда повторяет postinst, сохраняет уже проверенный CLI и не запускает VPN. Кнопка «Обновить CLI» и восстановление её журнала — отдельный механизм: [CLIENT-UPDATES.md](CLIENT-UPDATES.md).

`opkg remove asuswrt-merlin-trusttunnel` снимает интеграцию через штатное keep-config удаление, затем удаляет только собственный payload opkg. Приватный профиль, CLI и резерв кода сохраняются. Для полного удаления сначала выполните native purge, затем удалите пакет; см. [UNINSTALL.md](UNINSTALL.md). Не используйте `opkg --autoremove`: общие библиотеки могут требоваться другим аддонам.

## Подготовка и восстановление alpha.13

Online/manual setup при отсутствии timeout сначала устанавливает только coreutils-timeout из уже настроенного Entware, проверив root/aarch64, native helper и выключенное состояние аддона. Maintainer scripts не вызывают opkg внутри opkg. Все последующие NVRAM-чтения ограничены 2 s + 1 s до SIGKILL, частичный stdout отбрасывается.

Новый код полностью копируется в приватный stage и проходит shell syntax до первой замены. Предыдущие каталоги, init и config с исходными правами остаются в /jffs/addons/trusttunnel/install-backups/install-*. При ошибке перемещения/подключения UI выполняется возврат собственных файлов, конфигурации и UI; чужие hooks/menu не восстанавливаются целиком. При неудаче ремонта UI возвращается ошибка с адресом резерва. Ошибка физического носителя может помешать и восстановлению; тесты stage/move/UI errors выполнены на host, реальные IPK/postinst failures alpha.13 ещё не проверены.

Для ограниченного журнала нужен штатный mkfifo firmware/BusyBox; preflight проверяет его наличие. Новая схема начинает работать после следующего запуска клиента. Она сохраняет PID настоящего binary и не устанавливает HTTP-служб.
