# Безопасность и ограничения

## Сделано в текущей версии

Веб-форма держит секреты в памяти страницы и разбирает tt:// без сетевых запросов. Сохранение использует HTTPS и RSA-OAEP/SHA-256: в native argv, форме и возможном журнале событий оказывается шифртекст, а закрытый ключ и расшифрованные данные остаются в приватном runtime. Это экспериментальный транспорт, совместимость с реальным httpd/CSRF требует проверки. Запасной путь — локальный JSON и SSH. Общие custom_settings новым UI не читаются и не изменяются. Download может получить обычные права ОС: установите 0600 перед переносом, удалите временные копии после импорта. Browser storage и автоматическое сохранение не используются. Generated TOML и журнал не публикуются под /www. Ошибки разбора JSON не выводят контекст с секретами. `skip_verification=false` не изменяется пользователем. Нет `eval`, sourcing пользовательских config-файлов и произвольных действий из WebUI.

Явное подтверждение lab-only, проверка Merlin/root и запрет live networking с TT_ROOT снижают вероятность случайного запуска на компьютере разработчика. `start` не равен успешному VPN handshake; `connection_verified=false` всегда. Учёт PID использует starttime и resolved executable path, включая /opt symlink.

Устанавливаются собственные guards и prohibit route; при pause/аварии процесса они не снимаются намеренно. Удаление не очищает чужие таблицы или все conntrack entries. Обновление собственной цепочки и перестановка jump выполняются restore-транзакциями; перестроение нескольких таблиц в целом не является единой транзакцией.

## Чего эти меры не доказывают

Это не аудит и не доказательство fail-closed поведения на ASUS. При refresh guards восстанавливаются до client preflight: отсутствие binary/endpoint не должно мешать восстановлению сетевой блокировки (проверено mock-тестами). Не проверены: ранняя загрузка до /opt, firewall rebuild до callback, отказ USB/Entware, аппаратный flow cache/runner/CTF, чужой ACCEPT выше guard после reconcile, coexistence с transparent proxy, очистка или создание правил сторонним аддоном. Никаких обещаний нулевого окна утечки в этих случаях.

Проверка ctf_disable=1 неполна для HND: требуются отдельные наблюдения и packet capture. NAT/DNS forwarding, reverse path filtering и правильность адресации возвратных пакетов проверяются только реальным трафиком.

При повреждении runtime ownership-файла аддон должен отказать из-за занятых ресурсов, а не угадывать их принадлежность. Ручное вмешательство root и злонамеренный другой addon выходят за доверительную границу: у них уже полный доступ к системе и секретам.

Файл публичного статуса содержит hostname сервера и non-secret сетевую политику, то есть часть топологии. Доступ к `/user/trusttunnel/status.json` необходимо проверить без login/cookies на конкретной прошивке. До проверки не следует открывать WebUI на WAN. Родительская сессия/CSRF защита Merlin не проверена браузерным preview и должна войти в аппаратную приёмку.

Локальный журнал самого клиента потенциально может содержать чувствительные сведения. Он остаётся с правами 0600 в каталоге 0700 и не выгружается автоматически. Ограничение размера выполняется периодически, не является строгой границей памяти/диска в момент интенсивного вывода.

## Поставка

Стороннего binary нет. install-client.sh требует заданный SHA-256, но доверие к источнику этого hash остаётся обязанностью оператора. Проверка ELF header — это проверка формата/архитектуры, не гарантия происхождения, ABI или безопасности. На роутере никогда не исполняется автоматически скачанный install script.

При сообщении об ошибках не прикладывать реальные endpoint JSON, client TOML, сертификаты с private keys, полный process environment или журнал без просмотра. Для воспроизведения достаточно обезличенной политики, версии кода/прошивки, названий интерфейсов и read-only сведений о таблицах.

## Выбранные сети и секреты

IPv6 блокировка действует на все выбранные bridge целиком, IPv4 фильтруется парами bridge+source CIDR. Неотмеченные сети не включаются в план. SSID получают реальные имена через интерфейсы NVRAM и участников bridge; несколько SSID общего L3 bridge представлены одной строкой. Привязка bridge не читается из редактируемого DOM. Исчезнувшие сети нельзя сохранять как доступные.

Парсер tt:// и валидатор JSON ограничивают размер входа, поля и структуру. Данные не исполняются как код. DER/PEM framing validation не является проверкой X.509 доверия. Неподдержанные custom_sni/client_random, отключение TLS verification и literal IPv6 endpoint отклоняются. Неизвестные TLV теги и last-wins дубли обрабатываются по спецификации с предупреждением.

Новый канал сверяет ревизию под lock и не заменяет общие settings. История ID ограничена runtime/сутками; это не бесконечная защита от повторов после перезагрузки. Ключ передачи живёт до 30 минут; при потере ответа UI не утверждает, что запись состоялась. Установщик сохраняет backup перед overwrite, но не является полной транзакцией firmware menu/hooks.

Активное применение использует persistent journal и временный карантин, однако атомарность нескольких таблиц и отсутствие окон при firmware reload/ранней загрузке этим не доказаны. Откат зависит от cron, времени и Entware; отказ восстановления удерживает guards и может требовать SSH. Изменение DHCP/состава сетей вне аддона не переносит старые source CIDR автоматически. Выбор /32 не обеспечивает идентификацию устройства по MAC и не ограничивает IPv6 одним устройством.

Проверка подписи в `tools/verify-client.sh` использует отдельный временный GPG keyring и закреплённый upstream fingerprint. Ветки принятия/отказа проверяются с GPG stub; настоящий бинарник и подпись релиза не проверялись. Installer дополнительно сверяет hash/ELF aarch64 и сохраняет предыдущий binary, но не подтверждает ABI или версию содержимого самостоятельно.

Пользовательский сертификат дополнительно проверяется на роутере до импорта и генерации TOML: каждый PEM-блок должен успешно разбираться `openssl x509`. Некорректный первый или последующий блок, посторонний текст и незакрытые блоки отклоняются. Без OpenSSL непустой custom certificate не принимается; пустое поле использует обычное хранилище доверия клиента. Эта проверка предотвращает молчаливый fallback upstream при ошибке разбора, но не заменяет проверку TLS при соединении.

DNS из tt:// сохраняется без подстановки и без публикации URL в status. Политика schema3 не содержит собственного резолвера. Пустой DNS блокирует запуск; внутренний адрес DNAT 192.0.2.53 используется только для передачи DNS в обработчик клиента и не должен отправляться как внешний DNS-запрос. Перед запуском проверяется отсутствие такого локального адреса. Этот путь проверен по коду upstream и mock-тестами, но требует WAN capture на AX86U.

Верхнеуровневые `exclusions` — намеренно разрешённый прямой выход из TrustTunnel. WebUI предупреждает о раскрытии адреса провайдера, широких CIDR и `*:порт`; `*:53` отдельно отмечен как возможный прямой DNS. Вход ограничен документированными доменами/wildcard и IPv4-формами, нормализуется и генерируется через JSON quoting. Исключения не публикуются в status и не переносятся в `listener.tun.excluded_routes`. Это сохраняет владение системными маршрутами за аддоном, но реальную область обхода, разрешение доменов и поведение при сбое клиента нужно подтвердить WAN capture на AX86U.
