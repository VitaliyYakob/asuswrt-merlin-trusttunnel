# Безопасность и ограничения

## Сделано в текущей версии

Веб-форма держит секреты в памяти страницы и разбирает tt:// без сетевых запросов. Сохранение использует HTTPS и RSA-OAEP/SHA-256: в native argv, форме и возможном журнале событий оказывается шифртекст, а закрытый ключ и расшифрованные данные остаются в приватном runtime. Это экспериментальный транспорт, совместимость с реальным httpd/CSRF требует проверки. Запасной путь — локальный JSON и SSH. Общие custom_settings новым UI не читаются и не изменяются. Download может получить обычные права ОС: установите 0600 перед переносом, удалите временные копии после импорта. Browser storage и автоматическое сохранение не используются. Generated TOML и журнал не публикуются под /www. Ошибки разбора JSON не выводят контекст с секретами. `skip_verification=false` не изменяется пользователем. Нет `eval`, sourcing пользовательских config-файлов и произвольных действий из WebUI.

Явное подтверждение lab-only, проверка Merlin/root и запрет live networking с TT_ROOT снижают вероятность случайного запуска на компьютере разработчика. `start` не равен успешному VPN handshake; `connection_verified=false` всегда. Учёт PID использует starttime и resolved executable path, включая /opt symlink.

Устанавливаются собственные guards и prohibit route; при pause/аварии процесса они не снимаются намеренно. Удаление не очищает чужие таблицы или все conntrack entries. Обновление собственной цепочки и перестановка jump выполняются restore-транзакциями; перестроение нескольких таблиц в целом не является единой транзакцией.

## Чего эти меры не доказывают

Это не аудит и не доказательство fail-closed поведения на ASUS. При refresh guards восстанавливаются до client preflight: отсутствие binary/endpoint не должно мешать восстановлению сетевой блокировки (проверено mock-тестами). Не проверены: ранняя загрузка до /opt, firewall rebuild до callback, отказ USB/Entware, аппаратный flow cache/runner/CTF, чужой ACCEPT выше guard после reconcile, coexistence с transparent proxy, очистка или создание правил сторонним аддоном. Никаких обещаний нулевого окна утечки в этих случаях.

Проверка ctf_disable=1 неполна для HND: требуются отдельные наблюдения и packet capture. NAT/DNS forwarding, reverse path filtering и правильность адресации возвратных пакетов проверяются только реальным трафиком.

При повреждении runtime ownership-файла аддон должен отказать из-за занятых ресурсов, а не угадывать их принадлежность. Ручное вмешательство root и злонамеренный другой addon выходят за доверительную границу: у них уже полный доступ к системе и секретам.

Файл публичного статуса содержит hostname сервера и non-secret сетевую политику, то есть часть топологии. Доступ к `/user/trusttunnel/status.json` необходимо проверить без login/cookies на конкретной прошивке. До проверки не следует открывать WebUI на WAN. Родительская сессия/CSRF защита Merlin не проверена браузерным preview и должна войти в аппаратную приёмку.

Локальный журнал самого клиента потенциально может содержать чувствительные сведения. Он остаётся с правами 0600 в каталоге 0700 и не выгружается автоматически. Начиная с alpha.13 новые запуски клиента используют отдельный потребитель FIFO с порциями по 4096 байт: файл ограничен 1 MiB, временный хвост — 512 KiB. Читатель и клиент закрывают FD контроллера; прежняя периодическая обрезка остаётся защитой для старого способа запуска. Offline burst/EOF проверены; затраты на реальном AX86U ещё не измерены.

## Поставка

Стороннего binary нет. install-client.sh требует заданный SHA-256, но доверие к источнику этого hash остаётся обязанностью оператора. Проверка ELF header — это проверка формата/архитектуры, не гарантия происхождения, ABI или безопасности. Установка по ссылке выполняется по явной команде пользователя: HTTPS-скрипт из выбранного репозитория закрепляет хеш IPK и проверяет его до извлечения кода. Подписи самого IPK нет; хеш не даёт независимой аутентификации первого скрипта. При первоначальной установке CLI отдельно проверяются закреплённые хеши и настоящая GPG-подпись.

При сообщении об ошибках не прикладывать реальные endpoint JSON, client TOML, сертификаты с private keys, полный process environment или журнал без просмотра. Для воспроизведения достаточно обезличенной политики, версии кода/прошивки, названий интерфейсов и read-only сведений о таблицах.

## Выбранные сети и секреты

IPv6 блокировка действует на все выбранные bridge целиком, IPv4 фильтруется парами bridge+source CIDR. Неотмеченные сети не включаются в план. SSID получают реальные имена через интерфейсы NVRAM и участников bridge. SSID общего L3 bridge показаны отдельными строками с подтверждёнными по драйверу клиентами, но используют общую IPv4-политику. При неоднозначной/отсутствующей ассоциации клиент не показывается как принадлежащий SSID. Привязка bridge не читается из редактируемого DOM. Исчезнувшие сети нельзя сохранять как доступные.

Парсер tt:// и валидатор JSON ограничивают размер входа, поля и структуру. Данные не исполняются как код. DER/PEM framing validation не является проверкой X.509 доверия. Неподдержанные custom_sni/client_random, отключение TLS verification и literal IPv6 endpoint отклоняются. Неизвестные TLV теги и last-wins дубли обрабатываются по спецификации с предупреждением.

Новый канал сверяет ревизию под lock и не заменяет общие settings. История ID ограничена runtime/сутками; это не бесконечная защита от повторов после перезагрузки. Ключ передачи живёт до 2 часов; при потере ответа UI не утверждает, что запись состоялась. Установщик сохраняет backup перед overwrite, но не является полной транзакцией firmware menu/hooks.

Активное применение использует persistent journal и временный карантин, однако атомарность нескольких таблиц и отсутствие окон при firmware reload/ранней загрузке этим не доказаны. Откат зависит от cron, времени и Entware; отказ восстановления удерживает guards и может требовать SSH. Изменение DHCP/состава сетей вне аддона не переносит старые source CIDR автоматически. Выбор /32 не обеспечивает идентификацию устройства по MAC и не ограничивает IPv6 одним устройством.

Проверка подписи в `tools/verify-client.sh` использует отдельный временный GPG keyring и закреплённый upstream fingerprint. Ветки принятия/отказа на host проверяются с GPG stub; настоящая подпись CLI 1.1.5 и обновления 1.1.7 проверена на AX86U, в объёме TEST-REPORT. Installer дополнительно сверяет hash/ELF aarch64 и сохраняет предыдущий binary, но не подтверждает ABI или версию содержимого самостоятельно.

Пользовательский сертификат дополнительно проверяется на роутере до импорта и генерации TOML: каждый PEM-блок должен успешно разбираться `openssl x509`. Некорректный первый или последующий блок, посторонний текст и незакрытые блоки отклоняются. Без OpenSSL непустой custom certificate не принимается; пустое поле использует обычное хранилище доверия клиента. Эта проверка предотвращает молчаливый fallback upstream при ошибке разбора, но не заменяет проверку TLS при соединении.

DNS из tt:// сохраняется без подстановки и без публикации URL в status. Политика schema3 не содержит собственного резолвера. Пустой DNS блокирует запуск; внутренний адрес DNAT 192.0.2.53 используется только для передачи DNS в обработчик клиента и не должен отправляться как внешний DNS-запрос. Перед запуском проверяется отсутствие такого локального адреса. Этот путь проверен по коду upstream и mock-тестами, но требует WAN capture на AX86U.

Верхнеуровневые `exclusions` — намеренно разрешённый прямой выход из TrustTunnel. WebUI предупреждает о раскрытии адреса провайдера, широких CIDR и `*:порт`; `*:53` отдельно отмечен как возможный прямой DNS. Вход ограничен документированными доменами/wildcard и IPv4-формами, нормализуется и генерируется через JSON quoting. С alpha.4 список исключений публикуется в status для редактирования без повторного ввода учётных данных; это раскрывает имена исключённых доменов и адреса на тех же условиях доступа, что и остальные ресурсы WebUI Merlin. Сервер принимает отдельный запрос только с полем exclusions, под блокировкой объединяет его с приватным endpoint, проверяет ревизию и полную схему; активные изменения идут через существующую транзакцию. Пароль, username, DNS URL и сертификат не возвращаются. Исключения не переносятся в `listener.tun.excluded_routes`. Это сохраняет владение системными маршрутами за аддоном, но реальную область обхода, разрешение доменов и поведение при сбое клиента нужно подтвердить WAN capture на AX86U.

## Ручные обновления CLI (alpha.7)

Новый updater принимает только официальный Linux aarch64 release asset, повторно сверяет metadata, hash архива, закреплённую GPG-подпись самого binary, архитектуру и версию. Публичный ключ поставляется с аддоном; произвольных URL/ключей и remote shell нет. Загрузка не задерживает refresh guards; замена выполняется под повторно взятой блокировкой. Предыдущий binary/hash и атомарный журнал сохраняются до завершения. Recovery не перезаписывает неизвестный hash/symlink/каталог. Прерывание не означает explicit disable; guards сохраняются в алгоритме. После смены binary несовпадающие metadata версии/кандидата не используются в панели.

Это локально проверенный алгоритм, не обещание отсутствия утечек на HND. Подлинная подпись 1.1.7 и текущая конфигурация проверены на AX86U, пользователь подтвердил сайты/VPN IP после обновления и блокировку во время pause. Реальные сбои запуска/питания/USB, все варианты конфигурации и отсутствие утечек во время обновления ещё требуют контролируемой аппаратной проверки. Пассивный рост счётчиков не является тестом блокировки при обрыве.

## Дополнения alpha.13

Публичный endpoint содержит только configured, exclusions и protocol/MTU/anti_dpi. Partial settings принимает ровно три последних поля, объединяет их с приватным endpoint под lock, валидирует полный результат и применяет существующий journalled trial. DNS/credentials/certificate нельзя передать этим запросом. Экспорт для поддержки использует отдельный allowlist агрегатов/версий/кодов, исключая hostname, адресацию, SSID, MAC, имена устройств, credentials и произвольные будущие диагностические поля.

Uptime и boot identity определяют trial/retry; legacy journal без нового таймера истекает консервативно. Новый CLI требует пользовательского подтверждения работы после запуска; само наличие TUN не подтверждает соединение. Старые WebUI aliases удалены, сохранены операции с ID и документированный SSH CLI.

18.10.2026 анонимный GET к ASP/status/transfer на AX86U/alpha.12 возвращал login response с правильным Host; повтор 19.10.2026 на установленной alpha.13 дал тот же результат; полный auth/CSRF/WAN набор остаётся NOT RUN. Опциональный tools/check-webui-access.sh не передаёт cookies, не делает управляющих POST, не печатает ответ, требует проверяемый HTTPS сертификат. Он не заменяет полную приёмку.

Release workflow alpha.13 готовит GitHub/Sigstore provenance для manifest и пакетов после полного успешного CI того же коммита. Подписанное свидетельство проверяется на компьютере GitHub CLI с привязкой к репозиторию и signer workflow; приватный долговечный ключ в роутер/репозиторий не добавляется. Штатный router bootstrap пока проверяет закреплённый SHA-256, не Sigstore: первая команда установки по-прежнему доверяет выбранному HTTPS-источнику. Точные запуски CI и процесса подписи указаны в TEST-REPORT.md; наличие workflow или неподписанного manifest не является доказательством успешной проверки.
