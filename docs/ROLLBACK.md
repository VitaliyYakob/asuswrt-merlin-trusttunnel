# Резервные копии и откат

Обычный SSH-импорт endpoint/policy допускается после `trusttunnel.sh disable`. Это намеренно возвращает обычную маршрутизацию выбранным сетям. В версии 0.3 веб-сохранение активных настроек использует отдельную транзакцию с карантином и не требует отключения.

При незавершённой транзакции сначала нажмите **Откатить** либо выполните `trusttunnel.sh recover`. Подтверждение доступно только для фазы trial до её срока. Cron раз в минуту и boot повторяют восстановление истёкшей/незавершённой транзакции. Не удаляйте журнал `config/transaction` и маркеры владения вручную: при неуспешном восстановлении они нужны для сохранения блокировок и повторной попытки. Обычные start/pause/disable/import/upgrade запрещены до завершения этой процедуры.

При успешной валидации перед записью сохраняется прежний JSON как `.previous` (0600). Backup failure прекращает импорт. Резерв — одна предыдущая версия, а не история всех изменений. При импорте из `.previous` источник должен читаться до замены backup; это покрыто отдельной регрессией.

```sh
CTL=/jffs/addons/trusttunnel/trusttunnel.sh
"$CTL" disable
"$CTL" import-endpoint /jffs/addons/trusttunnel/config/endpoint.json.previous
"$CTL" import-policy /jffs/addons/trusttunnel/config/policy.json.previous
```

Импорт не запускает VPN автоматически. Проверяйте код завершения каждой команды; восстановление двух файлов — две отдельные операции.

Перед переустановкой копируются только прежние собственные файлы аддона и его Entware init в `install-backups/install-ДАТА.СЛУЧАЙНЫЙ_СУФФИКС/`. Backup создаётся до перезаписи, путь выводится установщиком. Это не атомарное обновление всей системы: автоматического отката menu bind/hooks после каждого вида сбоя установки пока нет.

Для восстановления кода отключите аддон и скопируйте из выбранного проверенного каталога backup `lib`, `share`, `web`, `trusttunnel.sh`, `trusttunnel_page.asp` обратно в `/jffs/addons/trusttunnel/`; верните `S99trusttunnel` в `/opt/etc/init.d/`, если он был сохранён. Затем выполните `trusttunnel.sh install-webui`. Endpoint/policy находятся отдельно и этим не заменяются. Backup старой версии может не понимать schema3: перед запуском старого кода импортируйте совместимую старую policy.

Hooks до первоначального изменения сохраняются в `config/hook-backups/`. Не заменяйте весь общий hook старой копией без сравнения: другие аддоны могли дописать его позже. Удаление аддона использует собственные маркеры и сохраняет чужие строки.

`sh uninstall.sh --confirm-release-traffic` снимает собственные правила, страницу, hooks, cron и init; код, configuration и клиентский binary остаются для восстановления. Git содержит исходный Template первым коммитом и проверенную рабочую версию отдельным коммитом.

С версии 0.2.1 импорт policy schema1/2 преобразует её в schema3, удаляя устаревший отдельный DNS. Резерв перед заменой сохраняет точные прежние данные установленного файла. Восстановление этой копии через новый контроллер снова применяет нормализацию. Для отката к коду 0.2.0 нужна совместимая политика прежнего формата; нельзя запускать старый код поверх schema3 без её восстановления.

Версия 0.3 сохраняет schema4 без преобразования в schema3. При откате к коду 0.2.x сначала подготовьте совместимую политику; не отбрасывайте локальные исключения и привязки молча.

## Проверка и возврат бинарника клиента

На компьютере с GnuPG отдельно получите официальный публичный ключ и сверяйте fingerprint с upstream `VERIFY_RELEASES.md`. Затем:

```sh
sh tools/verify-client.sh trusttunnel_client trusttunnel_client.sig trusttunnel-public-key.asc
```

Команда не скачивает ключи, не запускает binary и не меняет личный keyring. Она печатает только SHA-256 после проверки подписи и закреплённого fingerprint. Передайте этот hash установщику на роутере. Источник ключа: [официальная инструкция v1.1.5](https://github.com/TrustTunnel/TrustTunnelClient/blob/v1.1.5/VERIFY_RELEASES.md).

Перед заменой installer сохраняет `trusttunnel_client.previous` и `.previous.sha256` в `/opt/trusttunnel/bin/`. После явного отключения можно передать предыдущий бинарник и его сохранённый hash тому же `tools/install-client.sh`. Вход сначала копируется во временный файл, поэтому повторное использование `.previous` не уничтожает восстанавливаемую версию. После замены клиент автоматически не запускается. Резерв хранит только одну предыдущую версию.
