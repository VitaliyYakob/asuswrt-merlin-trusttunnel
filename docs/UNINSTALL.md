# Удаление TrustTunnel

В alpha.6 установочный архив и каталог `/jffs/addons/trusttunnel/` содержат `uninstall.sh`. По умолчанию скрипт только показывает состав удаления. Выполнять через SSH из основной сети. Действительное удаление намеренно возвращает выбранные сети к обычной маршрутизации Merlin.

## Посмотреть состав, ничего не менять

```sh
sh /jffs/addons/trusttunnel/uninstall.sh --dry-run
```

Отчёт содержит пути, без содержимого подключения, паролей или журналов. Запуск не останавливает VPN и не меняет файлы. Проверяется целостность установленного клиента по сохранённым SHA-256. Для старой версии сначала установите alpha.6: она добавляет механизм удаления и отметку владельца каталога.

## Снять интеграцию, сохранить настройки

```sh
sh /jffs/addons/trusttunnel/uninstall.sh --keep-config --confirm-release-traffic
```

Останавливает принадлежащий аддону процесс, снимает собственные маршруты/firewall, страницу VPN, помеченные блоки hooks/menu, cron `TrustTunnelMerlin`, свой init и устаревший ключ `ttm_policy` в общих настройках. Код, конфигурация, резервные копии и клиент остаются для переустановки. Прежняя команда `sh uninstall.sh --confirm-release-traffic` сохраняет этот смысл.

## Удалить собственные файлы и приватные данные

```sh
sh /jffs/addons/trusttunnel/uninstall.sh --purge --confirm-release-traffic --confirm-delete-data
```

После снятия и проверки интеграции удаляет:

- `/jffs/addons/trusttunnel`: код, подключение/пароль, исключения, policy и внутренние резервные копии.
- `/tmp/trusttunnel`: приватный TOML, журнал, ключи передачи, операции и runtime-файлы.
- Проверенные `trusttunnel_client`, его предыдущую версию и их digest-файлы из `/opt/trusttunnel/bin`. Непустые каталоги с посторонними файлами остаются.
- Каталоги установки/проверки из ограниченного списка `ttm-setup-*`, `trusttunnel-install-*`, `ttm-connect-probe.*`, `ttm-alpha5-trial.*` **только с отметкой владельца `.trusttunnel-owned`**. Новый setup создаёт её самостоятельно. Старые каталоги без доказательства происхождения лишь перечисляются; не добавляйте отметку к чужому каталогу.

Сначала разрешите незавершённое пробное применение через подтверждение/откат в панели. При ошибке остановки, удаления правил, проверки клиента или интеграции полная очистка не продолжается; конфигурация и код сохраняются до этапа удаления файлов. Повторите команду после устранения причины. При ошибке файлового удаления возможна частичная очистка: не считайте её успешной, ориентируйтесь на код возврата и оставшиеся пути. При необходимости используйте сохранённый установочный архив.

Перед изменением общих hooks/settings сохраняются копии с прежними правами; полная очистка намеренно удаляет и эти копии внутри аддона. Нужные вам резервные копии подключения заранее сохраните самостоятельно вне удаляемых каталогов. Purge не создаёт новую скрытую копию пароля.

## Что сохраняется

Общие пакеты Entware (`jq-full`, `flock`, `curl` и другие), сторонние hooks/menu/настройки, Wi-Fi, NVRAM и режим аппаратного ускорения не удаляются. Пустые hooks удаляются только если установщик записал, что создал их сам; существовавшие ранее сохраняются. Общий menu bind сохраняется, поскольку им пользуются другие аддоны. Пустой `/tmp/trusttunnel-menu.lock` остаётся до перезагрузки, чтобы не создавать гонку разных экземпляров меню.

Системный журнал роутера не очищается целиком. Файлы, скачанные на компьютер, история браузера/SSH и старые неотмеченные диагностические каталоги требуют отдельной проверки. Обычное удаление не гарантирует физическое стирание прежних данных с flash/USB. Если клиентский binary изменён или есть symlink/вложенный mount в удаляемом пути, purge отказывается от удаления вместо расширения области очистки.

Механизм покрыт локальными проверками с подменёнными сетевыми командами. Полный purge alpha.6 выполнен на AX86U; точный объём и последующая переустановка описаны в TEST-REPORT. Это не подтверждает полный live lifecycle нового IPK alpha.10.

## Журнал обновления CLI (alpha.7)

Удаление отказывается работать при наличии `config/client-update-journal.json`: сначала нужно завершить восстановление клиента, чтобы не уничтожить единственный известный резерв. Прерванное обновление восстанавливается через `recover-client`, затем `refresh` сохраняет намерение enabled/paused. Неизвестные staging-файлы в `/opt/trusttunnel/bin` сохраняются и показываются в dry-run, а не удаляются по шаблону. Общие GnuPG/tar/timeout и другие пакеты Entware не удаляются.

## Установка через IPK (alpha.10)

`opkg remove asuswrt-merlin-trusttunnel` вызывает штатное keep-config удаление. Оно снимает интеграцию и возвращает обычную маршрутизацию, но сохраняет приватный профиль, CLI и резерв кода. После успешного prerm opkg удаляет только пакетные исходники в `/opt/share/asuswrt-merlin-trusttunnel`. Ошибка native removal останавливает удаление пакета. При upgrade prerm проверяет выключенное состояние, а не выполняет uninstall.

Для полной очистки сначала выполните native purge с обоими подтверждениями, затем `opkg remove asuswrt-merlin-trusttunnel`. Уже удалённый controller не мешает этому последнему шагу. Не применяйте `--autoremove`: общие зависимости остаются другим аддонам. Исходные SSH-установки не регистрировали пакет и не требуют opkg remove.
