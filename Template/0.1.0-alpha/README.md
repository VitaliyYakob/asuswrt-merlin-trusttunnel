# TrustTunnel Client Addon for ASUSWRT-Merlin

**Версия: 0.1.0-alpha.1 · реализация начата · оборудование не тестировалось.**

Аддон штатного WebUI: **VPN → TrustTunnel**. Никакого отдельного web-сервера, порта, контейнера, Node.js/Python-сервиса или собственной системы авторизации на роутере. Node.js и Python нужны только на компьютере разработчика для тестов и вспомогательных инструментов.

Исходная целевая платформа — **ASUS RT-AX86U / aarch64 / ASUSWRT-Merlin с Addons API и Entware**. Совместимость с конкретными версиями прошивки и ядра не подтверждена. Не заявляется поддержка всех ASUS, всех веток Merlin, ARM32 или MIPS.

> **Не устанавливать как защиту рабочего трафика.** Это лабораторная alpha с реальным кодом, но без проверки на устройстве. Локальные тесты не доказывают отсутствие утечек. Установка требует явного `--lab-only`; VPN не включается автоматически после установки.

## Что реализовано

- Страница VPN с управлением запуском, паузой с сохранением правил, перезапуском и отдельным отключением с возвратом обычной маршрутизации.
- Приватный импорт endpoint JSON по SSH; безопасная генерация TOML без исполнения конфигурации как shell-кода. TLS verification всегда включена.
- Настройка non-secret политики из WebUI: один LAN/guest bridge, до 32 приватных IPv4 CIDR, внешний IPv4 DNS.
- Собственная таблица 871, приоритеты 17100–17131 и цепочки `TTM*`; **нет изменения default route в main, fwmark или глобальной очистки conntrack**.
- Декларативный план сетевых команд, пригодный для просмотра без роутера; guard перед маршрутами, prohibit default, восстановление правил по событиям.
- Перенаправление TCP/UDP 53 выбранных IPv4-клиентов в туннель, включая запросы к IPv4-адресу DNS роутера. Системный dnsmasq/resolv.conf не меняется.
- Блокировка IPv6-транзита и IPv6 DNS к роутеру на **всём выбранном bridge**, с обязательным подтверждением в UI/политике.
- Проверка принадлежности PID по executable и start time, блокировка параллельных контроллеров через flock; клиент не наследует lock FD.
- Hooks Merlin, Entware init, cron-reconcile, статус без учётных данных, ограничение локального журнала, резервные копии изменяемых hooks.
- Независимые тесты валидаторов/TOML/планов/редактора hooks/menu, модель сетевых команд, frontend-тесты, offline HTML preview и CI-конфигурация.

**Не реализовано:** ввод пароля/сертификата и импорт полного TOML непосредственно в WebUI, доменные/GeoIP-списки, multi-profile/failover, полноценная IPv6-маршрутизация, интеграция в VPN Director, встроенное автоматическое обновление, подтверждение handshake/доступности внешнего ресурса через TUN, готовые проверенные `.ipk`-пакеты. Статус намеренно не показывает «Connected» по одному наличию процесса.

## Просмотр и тестирование без оборудования

Откройте `preview/index.html`: это самодостаточный демонстрационный интерфейс. Команды в нём никуда не отправляются; реальные настройки Merlin и состояние VPN он не читает.

На Linux/macOS-компьютере разработчика нужны Python 3.11+, Node.js, jq, BusyBox, стандартные shell/awk и flock для части файловых тестов. Удобнее использовать Linux либо Linux VM. На macOS инструменты flock и BusyBox потребуется установить отдельно.

```sh
make test
make preview

./addon/trusttunnel.sh validate endpoint examples/endpoint.example.json
./addon/trusttunnel.sh validate policy examples/policy.example.json
./addon/trusttunnel.sh plan guard examples/policy.example.json
```

Команды `validate`, `render`, `plan` **не изменяют сетевые настройки**. Вывод `render` содержит пароль, поэтому не следует добавлять его в общий журнал или публиковать.

Изолированное файловое окружение:

```sh
export TT_ROOT="$PWD/.lab-root"
./addon/trusttunnel.sh import-endpoint examples/endpoint.example.json
./addon/trusttunnel.sh import-policy examples/policy.example.json
./addon/trusttunnel.sh status
```

При заданном `TT_ROOT` реальные сетевые операции запрещены. Тесты сетевого исполнителя используют отдельные подменные команды; они не обращаются к сетевым таблицам хоста.

## Конфигурация

Образцы находятся в `examples/`. Все IP в них — примеры, а не сведения о вашем роутере или сервере. **Нельзя предполагать, что br1 соответствует вашей гостевой сети.** Перед испытанием это нужно установить по реальной конфигурации.

Endpoint содержит hostname, addresses, username/password, http2/http3, certificate, dns_upstreams, anti_dpi, MTU и необязательный WAN interface. Назначения upstream в alpha допускают hostname:port или IPv4:port; bracketed IPv6 endpoint не поддержан.

Схема генерации соответствует исследованной документации TrustTunnelClient **v1.1.5**. Это зафиксированная исходная версия схемы, не заявление о проверке бинарника или о последнем доступном релизе. Бинарники TrustTunnel не включены в этот проект.

Для преобразования стандартного TOML на компьютере разработчика:

```sh
python3 tools/convert-config.py original-client.toml endpoint.json
./addon/trusttunnel.sh validate endpoint endpoint.json
```

Конвертер создаёт новый файл с правами 0600 и не перезаписывает существующий. Неизвестные endpoint-параметры, отключённая проверка сертификата, client_random и внутренние selective/exclusions отклоняются, а не молча теряются. Маршруты, DNS системы и IPv6 далее управляются аддоном. Пустой список upstream DNS заменяется явно указанным в конвертере примером `tls://1.1.1.1`; его следует проверить и при необходимости изменить в JSON.

## Лабораторная установка, когда появится оборудование

Сначала прочитайте `docs/HARDWARE-TESTS.md` и обеспечьте независимый доступ к роутеру. Не проводите первое испытание на единственном удалённом канале управления.

1. Проверить Entware `/opt`, Addons API, включённое выполнение пользовательских JFFS-скриптов, TUN и требуемые команды: `jq`, полноценный `ip`, `iptables`, `ip6tables`, оба `*-restore`, `flock`, `sha256sum`, `base64`, `cru`. Автоматическая установка зависимостей в alpha отсутствует. Отключить аппаратное ускорение/NAT acceleration и проверить результат для своей HND-платформы, а не только одно nvram-значение.
2. Распаковать исходники на роутере и выполнить `sh install.sh --lab-only`. Это устанавливает страницу, hooks и init-скрипт; не скачивает клиент, не импортирует пример в рабочую конфигурацию и не включает VPN.
3. Отдельно получить подходящий официальный client binary. Проверить его источник и SHA-256. Лабораторный `tools/install-client.sh LOCAL_BINARY EXPECTED_SHA256` проверяет hash и ELF64 aarch64, но **не подтверждает ABI, статическую линковку или совместимость ядра**.
4. Подготовить реальные endpoint/policy JSON, перенести по SSH с приватными правами и импортировать:

```sh
CTL=/jffs/addons/trusttunnel/trusttunnel.sh
"$CTL" import-endpoint /tmp/endpoint.json
"$CTL" import-policy /tmp/policy.json
rm -f /tmp/endpoint.json /tmp/policy.json
```

5. Открыть **VPN → TrustTunnel**, проверить bridge/источники и ограничения IPv6, затем выполнить испытание запуска. Если `ctf_disable` не равен 1, runtime preflight откажет. Сам по себе `ctf_disable=1` не является доказательством отключения HND runner/flow cache; это отдельный аппаратный критерий.

Постоянные private-файлы: `/jffs/addons/trusttunnel/config/` (0700), endpoint/policy (0600). Сгенерированный TOML, PID и клиентский журнал: `/tmp/trusttunnel/` (0700). Публично читаемые через WebUI-файлы содержат только код страницы и ограниченный статус; реальную авторизацию `/user/…` необходимо проверить на прошивке.

## Значение кнопок

| Команда | Назначение |
|---|---|
| `start` | Запрашивает включение защиты, строит правила и запускает клиент. Неуспешный запуск не считается отключением. |
| `pause` | Останавливает процесс, но сохраняет правила и признак включения. Пауза переживает перезагрузку. |
| `restart` | Перезапускает процесс; не снимает собственные защитные правила между остановкой и запуском. |
| `disable` | Явно удаляет свои правила и возвращает трафик к обычной обработке Merlin. Это не принудительный WAN в обход других VPN. |
| `refresh` | Восстанавливает правила и маршрут при включённом аддоне; учитывает паузу. |
| `status` | Показывает наблюдаемое состояние; `connection_verified` в этой версии всегда `false`. |

Состояния `paused_protected`/`blocked_or_start_failed` описывают намерение контроллера, а не сертификат отсутствия утечек. Обращайте внимание на `last_result` и свежесть timestamp. Cron обновляет backend примерно раз в минуту; WebUI читает готовый JSON каждые пять секунд, не создавая отдельного API-сервера.

## Удаление и восстановление

`sh uninstall.sh --confirm-release-traffic` вызывает явное отключение, снимает только собственные hooks/menu/сетевые объекты и удаляет init-скрипт. Исходники, учётные данные и бинарник **сохраняются намеренно** для восстановления/аудита; удалять их нужно отдельным осознанным действием после проверки. При ошибке удаления ownership сохраняется, а успешное отключение не заявляется.

Резервные копии hooks — `config/hook-backups/`. При проблеме сначала использовать SSH и read-only диагностику из `docs/HARDWARE-TESTS.md`. Не применять глобальные `iptables -F`, `ip rule flush` или `conntrack -F` ради этого аддона.
