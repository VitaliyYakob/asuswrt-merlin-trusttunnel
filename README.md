# TrustTunnel для ASUSWRT-Merlin

**0.3.0-alpha.1 · ASUS RT-AX86U / ARM64 / Entware · аппаратные испытания не выполнены.**

Нативная страница **VPN → TrustTunnel** с настройкой подключения и выбором домашних сетей для VPN. На роутере используется штатный WebUI Merlin и shell-контроллер; отдельного web-сервера, Node.js или Python на роутере нет.

Исходный `Template/` сохранён без изменений и зафиксирован первым коммитом Git. Рабочая версия находится в корне проекта. Исследование примеров и обоснование решений: [docs/RESEARCH.md](docs/RESEARCH.md).

## Что можно тестировать

- **Подключение вручную:** TLS hostname, серверы с портом, логин/пароль, HTTP/2 или HTTP/3, Anti-DPI, сертификат, DNS и MTU. Отдельного DNS для маршрутизации нет; значения из tt:// сохраняются без подмены и отображаются только для чтения.
- **Импорт `tt://`:** настоящий формат TrustTunnel TLV/Base64url, включая преобразование сертификатов DER → PEM. Проверка ограничений и предупреждения о несовместимых/повторяющихся полях.
- **Маршрутизация нескольких сетей:** основная и три гостевые, все сразу либо выбранные. Сети показаны по SSID; для них можно уточнять подсети или отдельные адреса `/32`. Bridge определяется автоматически и не редактируется в панели. До 16 bridge и 32 записей суммарно. Старая политика с одним bridge продолжает работать.
- **Управление:** запуск, пауза с сохранением правил, перезапуск, явное отключение. Статус показывает наблюдаемый процесс и TUN, а не неподтверждённый «Connected».
- **Восстановление:** приватные резервные копии конфигураций перед заменой, резерв прежних файлов аддона при переустановке, сохранение чужих hooks и сетевых правил.

В **0.3** добавлены четыре вкладки, импорт файла, приватное сохранение через HTTPS, ревизии и история операций, пробное применение работающей конфигурации с подтверждением/откатом, выбор устройств по IPv4 и локальные исключения. Новый канал не записывает `amng_custom`; браузер отправляет только зашифрованные части конфигурации. Работа этого канала на настоящем httpd Merlin ещё не проверена; экспорт и SSH остаются запасным способом.

## Быстрая проверка без роутера

Откройте [preview/index.html](preview/index.html) в браузере. Это интерактивный автономный интерфейс: ручной ввод, `tt://`, проверка и скачивание JSON работают; управляющие команды на роутер не отправляются. В нём используются примерные сети. Оформление повторяет классические формы Merlin; шапка ASUS и боковое меню в предпросмотре демонстрационные. На роутере навигацию создаёт сама прошивка.

На компьютере разработчика нужны Python 3.11+, Node.js, jq, BusyBox ash, flock и openssl:

```sh
make test
make preview
make package
# Дополнительно: Playwright JS и установленный Chromium
make browser-test
# Дополнительно: ShellCheck
make lint
```

На Linux BusyBox, jq и flock доступны в пакетах `busybox`, `jq`, `util-linux`. Node/Python нужны только на компьютере. Фактическая среда и результаты этой сессии: [docs/TEST-REPORT.md](docs/TEST-REPORT.md).

```sh
./addon/trusttunnel.sh validate endpoint examples/endpoint.example.json
./addon/trusttunnel.sh validate policy examples/policy.multinetwork.example.json
./addon/trusttunnel.sh plan guard examples/policy.multinetwork.example.json
```

Эти команды не меняют сеть. Для проверки файлового импорта используйте `TT_ROOT` — с ним живые сетевые команды запрещены:

```sh
export TT_ROOT="$PWD/.lab-root"
./addon/trusttunnel.sh import-endpoint examples/endpoint.example.json
./addon/trusttunnel.sh import-policy examples/policy.multinetwork.example.json
./addon/trusttunnel.sh status
```

## Основная и гостевые сети

Политика schema 3 связывает **bridge + исходную IPv4-подсеть**. Например:

```json
{
  "schema": 3,
  "networks": [
    {"lan_if": "br0", "sources": ["192.168.50.0/24"]},
    {"lan_if": "br2", "sources": ["192.168.52.0/24"]}
  ],
  "block_ipv6_bridge": true,
  "table": 871,
  "priority": 17100
}
```

В этом примере выбраны только `br0` и `br2`. На `br1` и `br3` аддон не добавляет свои правила. Это сохраняет обычную маршрутизацию Merlin, которая может включать другие VPN. Чтобы направить все сети, выберите все строки и проверьте их адресацию.

**SSID не равен bridge.** Панель сопоставляет имена Wi-Fi с фактическими участниками bridge и показывает их в списке. Интерфейсы назначаются автоматически; полей их ручного редактирования нет. Несколько SSID одной сети объединяются в одну строку. Если имя получить не удалось, показано «SSID не определён» и подсеть; выдуманных имён/сетей нет. Если сеть пропала, она отмечается недоступной и не может быть включена в новую политику.

В автономном preview используются явно демонстрационные SSID Home и Guest 1–3. На настоящем роутере список берётся из его текущего состояния. Гостевые SSID в одной подсети нельзя отдельно выбрать по имени; для разделения нужны реальные отдельные сети или адреса `/32`.

DNS берётся из `endpoint.dns_upstreams` конфигурации. Импорт `tt://` не подставляет `1.1.1.1` или другой сервер и не позволяет незаметно переопределить DNS в форме. Для ручного подключения DNS указывается при подготовке самого endpoint. Если DNS отсутствует, он сохраняется как пустой список, а запуск отклоняется с объяснением. Отдельное поле DNS маршрутизации удалено.

IPv4 выбранных источников и DNS TCP/UDP 53 направляются в туннель. IPv6-транзит и IPv6 DNS к самому роутеру блокируются **на каждом выбранном bridge целиком** — это явно подтверждается в форме. В разделе локальных ресурсов можно выбрать обнаруженные подсети для обычного доступа: правила возвращают трафик в фильтрацию Merlin, не отменяя гостевую изоляцию. Для такого доступа используются только маршруты собственной таблицы.

WebUI создаёт policy **schema4**, дополняя сети идентификатором их состава и `local_access`. Пример schema3 выше остаётся совместимым для SSH. Выбор DHCP-устройства заменяет широкие подсети списком /32; закрепление IP необходимо выполнить в DHCP Merlin. MAC не является условием маршрутизации.

## Первое испытание на AX86U

Версию Merlin ещё нужно установить. Начните с [аппаратной матрицы и диагностических команд](docs/HARDWARE-TESTS.md). Используйте одно тестовое устройство в гостевой сети и независимый доступ к SSH для отката.

1. Проверьте Addons API, включённые JFFS custom scripts/configs, рабочий Entware, `/dev/net/tun`, `jq`, `flock`, полный `ip`, `iptables`, `ip6tables`, оба `*-restore`, `sha256sum`, `base64`, `cru`; для пользовательского сертификата также `openssl` (проверка X.509). Аппаратное ускорение AX86U должно быть проверено отдельно; `ctf_disable=1` недостаточно для доказательства отключения HND runner/flow cache.
2. Распакуйте архив из `dist/` и запустите `sh install.sh --lab-only`. Установка не включает VPN и не скачивает бинарник клиента.
3. Отдельно получите **официальный TrustTunnelClient v1.1.5 Linux aarch64**, проверьте подпись/происхождение и SHA-256. `sh tools/install-client.sh LOCAL_BINARY EXPECTED_SHA256` проверяет hash и архитектуру, но не доказывает совместимость ABI/ядра Merlin.
4. Откройте **VPN → TrustTunnel** по HTTPS. Введите параметры, разберите `tt://` или импортируйте JSON/текстовый файл. Нажмите **Сохранить подключение** и дождитесь результата операции. Нужен OpenSSL на роутере; действующий пароль в форму не загружается, сохранение заменяет endpoint целиком.
5. Запасной путь: **Проверить и скачать конфигурацию**, ограничить права файла и перенести по SCP/SFTP в `/tmp/trusttunnel-endpoint.json`. Перед обычным SSH-импортом отключите аддон. В SSH:

```sh
chmod 600 /tmp/trusttunnel-endpoint.json
/jffs/addons/trusttunnel/trusttunnel.sh import-endpoint /tmp/trusttunnel-endpoint.json
# Только после успешного импорта:
rm /tmp/trusttunnel-endpoint.json
```

6. Выберите сети/устройства, при необходимости локальные ресурсы, подтвердите ограничение IPv6 и сохраните маршрутизацию. При включённом аддоне начинается пробное применение: проверьте доступ с устройств и подтвердите за 180 секунд. Без подтверждения cron/boot запускает откат; неуспешный откат сохраняет блокировки. Для SSH доступен `import-policy /tmp/trusttunnel-policy.json` при отключённом аддоне.
7. Запустите клиент. Проверяйте внешний IP и DNS **с выбранного LAN/guest устройства**, затем с невыбранного. Отдельно проверьте остановку клиента, паузу, перезагрузку, смену WAN и восстановление firewall. Появление TUN само по себе не является успешным тестом VPN.

Файлы конфигурации содержат пароль: удалите временные копии из загрузок компьютера после импорта. Пароль не сохраняется в browser storage. TOML и клиентский журнал находятся в приватном `/tmp/trusttunnel/`.

## Откат

```sh
# Вернуть обычную маршрутизацию, сняв собственные правила аддона:
/jffs/addons/trusttunnel/trusttunnel.sh disable
# Снять страницу, hooks и init (сохранив конфигурацию и бинарник):
sh uninstall.sh --confirm-release-traffic
```

При импорте старые политики schema1/2 преобразуются в schema3; устаревший `dns_ipv4` удаляется, а исходный файл сохраняется в `.previous`. Schema4 сохраняется без понижения. Обычный импорт включённой политики запрещён; новый веб-канал использует отдельную транзакцию.

Если есть незавершённое применение, сначала используйте **Откатить** либо `trusttunnel.sh recover`. До восстановления/подтверждения отключение, импорт и обновление заблокированы, чтобы не оставить несогласованные правила. Подробности: [ROLLBACK.md](docs/ROLLBACK.md).

Перед заменой `endpoint.json` и `policy.json` сохраняются соседние `.previous` с правами 0600. Для возврата предыдущей версии после отключения:

```sh
CTL=/jffs/addons/trusttunnel/trusttunnel.sh
"$CTL" import-endpoint /jffs/addons/trusttunnel/config/endpoint.json.previous
"$CTL" import-policy /jffs/addons/trusttunnel/config/policy.json.previous
```

Прежние файлы установленного аддона сохраняются в `/jffs/addons/trusttunnel/install-backups/`; hooks — в `config/hook-backups/`. Подробности восстановления файлов: [docs/ROLLBACK.md](docs/ROLLBACK.md). Не применяйте глобальные `iptables -F`/`ip rule flush`.

## Границы готовности

Локальные проверки не заменяют испытание на ASUS: ABI клиента, реальный HTTPS WebUI, CSRF, firewall hooks, DNS/IPv6 и HND acceleration пока не проверены. Также не реализованы доменные/GeoIP-списки, несколько VPN-серверов/failover, маршрутизация IPv6 и автоматическое обновление бинарника.
